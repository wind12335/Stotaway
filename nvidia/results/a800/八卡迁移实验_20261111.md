# A800 八卡迁移与实验记录

硬件：单机 8×A800-SXM4-80GB，驱动 580.65.06，`nvidia-smi topo -m` 任意 GPU 对均显示 NV8。数据均为独立进程初步测量，speedup = stock 耗时 / 候选耗时。

## 新 TP8 DX 原型

`stowaway_nvidia/dx8.py` 是同机 8 rank 多 peer 实验原型：NVSHMEM 对称缓冲、CUDA 流内等待与异步拷贝，逐 peer 分块 GEMM；使用共享 TP world group、不支持多组、多机或并发 context。M1024/K1024/N1024 和 M4096/K5120/N2176 两组，8 rank 各 4 次随机输入前向与 NCCL 基线对照均通过 `rtol=.03, atol=.02`；连续调用共多轮。

| M/K/N | AG stock / DX ms | AG speedup | RS stock / DX ms | RS speedup |
|---|---:|---:|---:|---:|
| 1024/1024/1024 | 0.1357 / 1.0761 | 0.126× | 0.1216 / 1.2365 | 0.098× |
| 4096/5120/2176 | 0.8170 / 0.9416 | 0.868× | 0.6560 / 0.7819 | 0.839× |
| 4096/640/5120 | 0.2483 / 0.6505 | 0.382× | 0.4882 / 0.7313 | 0.668× |
| 8192/5120/2176 第 1 轮 | 1.5175 / 1.4947 | 1.015× | 1.2546 / 1.1884 | 1.056× |
| 8192/5120/2176 第 2 轮 | 1.5298 / 1.7156 | 0.892× | 1.0763 / 1.1802 | 0.912× |
| 8192/640/5120 | 0.4142 / 0.6816 | 0.608× | 0.8147 / 1.1999 | 0.679× |
| 16384/5120/2176 | 2.8290 / 3.2837 | 0.862× | 2.2299 / 2.6597 | 0.838× |

每组是一次进程、每臂 6 组计时，每组 3 次调用，取 8 rank 最慢值的中位数；以上新增形状也各通过 8 rank 四轮数值检查。8192/5120/2176 的独立复测与第一轮方向相反，当前不能认定有稳定收益。逐 peer 调度开销大，这不是最终优化结果。数据 `/root/data/stowaway-nvidia/results/tp8_20261111/operator_*.json`。

## Megatron dense TP8

四层 H5120/FFN17408、40 heads/8 query groups、seq4096、MBS1/GBS2、BF16、full recompute、distributed optimizer DP1、mock data，local 层与诊断 TorchNorm；非完整 Qwen3 训练。12 步排除前 3 步后取中位：

| 方案 | 独立进程 ms/step | speedup（两次 stock 的中位为 226.55 ms） |
|---|---|---:|
| stock | 226.6、226.5 | 1.000× |
| 全部 DX | 229.9、229.0 | 0.987× |
| 仅 proj DX | 230.7 | 0.982× |

全部 DX 每 rank row/column 各命中 384 次；各组 12 步均无 skipped/NaN。DX 与 stock 的 loss 并非完全一致；一层同形状首步、8 rank 所有梯度以 `rtol=.02, atol=.002` 比较通过，不代表 12 步所有参数或长训练严格一致。首次适配因 column 输出 reshape 仍写死 2 卡失败，已修复；失败日志 `tp8_megatron_dx_r0_20261111.log` 保留。首步梯度快照验证后因磁盘空间回收，清单 `tp8_capture_cleanup_20261111.json`，报告 `megatron_grad_diff.json`。

同样四层、序列 8192 的两轮对照：stock 532.6、534.3 ms/step，全部 DX 540.9、541.1 ms/step；按进程中位数计算 533.45 / 541.0 = **0.986×**。每 rank row/column 各命中 384、无 skipped/NaN，没有专门梯度快照。

## Transformer Engine TP8

同四层载具，用 TE 层并将不开 `tp_comm_overlap` 的 TE 作基线，`UB_SKIPMC=1`、gloo bootstrap。stock 两次 182.2、183.0 ms，overlap 两次 176.3、175.5 ms；中位数 182.6 / 175.9 = **1.038×**。12 步无 skipped/NaN；层标志表明 overlap 已启用，不等于 profiler 时序证明。TE CUDA12 wheel 在当前 Python 平台的元数据警告仍在，作为诊断结果。

## 八卡小型 MoE

TP1/EP2、4 个数据并行组、两层、8 专家、H1024、专家 FFN512、seq512、GBS8、mock data；20 步排除前 3 步，上游 EP2 stock 50.1 ms，诊断性的 Triton SequentialExpertAdapter 1887.0 ms，约 **0.0265×**。候选每 rank 命中 40 次、0 fallback、无 skipped/NaN；每次读取 CPU offsets 并堆叠权重，固定网格极不适合该配置；没有单独数值捕获，不能作为合格速度结果。上游 dispatcher 并未替换为 NVSHMEM；现有 NVSHMEM EP 仍只支持 world=2。原始日志 `tp8_moe_{ep2_stock,gg}_r0_20261111.log`。

## Llama 3 70B：vLLM 八卡真实权重推理

vLLM 0.11、BF16、TP8、eager、单请求，输入 1024 token，输出 1 或 32 token；每种输出长度 4 个不同提示，先预热两次，计时包括 `LLM.generate` 调度和生成，不含模型加载与分词，取八卡最大耗时的中位数。输入来自模型文档，温度为 0，关闭前缀缓存。以下为单次进程的初步结果，不能代替独立复测；speedup 的基准为原版。

| 路径 | 1 token ms / speedup | 32 tokens ms / speedup | 输出与原版一致性 |
|---|---:|---:|---|
| 上游原版 | 139.967 / 1.000× | 1217.792 / 1.000× | 基准 |
| 序列并行，NCCL | 143.981 / 0.972× | 1220.820 / 0.998× | 1 token 4/4 一致；32 token 2/4 一致 |
| 序列并行，DX 列投影 | 192.785 / 0.726× | 1291.734 / 0.943× | 1 token 4/4 一致；32 token 2/4 一致 |

序列并行和 DX 各在全部八 rank 命中 8 次测量前向；decode 等其他形状回退原版。DX 是 TP8 的 NVSHMEM 多 peer 原型，只用于列投影，行投影使用 NCCL；既没有通过全部 token 一致性检查，也没有取得加速，不可作为合格的最终方案。提示哈希、token 和耗时保存在 `/root/data/stowaway-nvidia/results/tp8_20261111/vllm_llama70_{stock,stock_sp,dx_col}.json`，原始日志在 `results/raw/tp8_vllm_llama70_*_20261111.log`。推理初始化使用临时内存盘上的现有 vLLM 环境副本来减少 Lustre 读取等待。

## 完整模型训练与 Qwen3.6 状态

已尝试 Megatron Llama 3 70B 完整 80 层架构（H8192、FFN28672、64 头、8 query groups、TP8、seq1024、BF16、重计算、CPU Adam 状态卸载，mock data，随机初始化而非真实权重微调）。模型和优化器初始化完成并开始首步；观测到容器内存接近 800 GiB 限制，随后运行进程消失，日志没有完成的 iteration、也没有训练耗时或 DX 对照。环境状态发生重置后内存事件计数为零，不能确定终止原因；不能声称完整训练成功。日志 `tp8_megatron_llama70_stock_20261111.log`。

共享权重目录中存在 `Qwen3.6-27B`；其 `config.json` 声明 `Qwen3_5ForConditionalGeneration`，64 层为线性注意力与全注意力混合。代理后来恢复，按 Megatron 仓库依赖安装了 FLA 0.4.2 至迁移目录；64 层混合文本配置、随机初始化、mock data 的 TE 原版和 local DX 训练各完成 5 步。具体数值见 [端到端与预测器结果表](../端到端与预测器结果表.md)。尚未导入 HF 权重并验证等价性；按用户最新分工，Qwen 用于训练、Llama 用于推理。

## 未完成与限制

TP8 预测器尚未标定和接入；MoE NVSHMEM EP 仍为双卡限制；Async-TP、论文 1 原形态及完整模型训练尚无八卡 E2E 对照。现有 TP8 DX 仅是单机单 TP 组实验原型，尚不是完整、优化且可生产使用的 NVIDIA 迁移。需要先解决依赖与训练内存，之后逐项做数值门槛、重复计时和多形状测试。
