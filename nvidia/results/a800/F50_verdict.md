# F50 探针：预注册与结果

以下判据在采集数据前记录，来自 `A800迁移注意.md`；这些经验阈值不能代替对测量方案、噪声和不确定性的分析。

- 测量两进程，rank 0 发起；目的地分别为对端 CUDA IPC、对端 NVSHMEM、本卡 cudaMalloc、本卡 torch tensor。分别测试事件门控和值门控，以及默认 CUDA 连接数和 `CUDA_DEVICE_MAX_CONNECTIONS=1`。
- 每组在 GPU 流上排入睡眠，随后发 40 个操作，每个操作含 7 次 1 MiB 拷贝及各自的 4 字节票据；单独统计 host 入队总时间及分项。实际睡眠需校准并报告，不将异步等待或实验后的 GPU 同步计入 host 入队时间。
- 候选成立条件：对端目的地 host 总时间至少为适当本卡目的地 5 倍，且改变睡眠时长时 host 时间随之同比增长。候选不成立条件：对端与本卡小于 2 倍，且 40 个操作 host 总时间小于 5 ms。其他情况列为不确定或介于两者之间。
- 应报告重复次数、逐次结果、各组比较基准和噪声；如条件不能可靠复现则不做成立/不成立判断。跨平台机理不能仅凭比值断定，需进一步排除混杂因素。
- 在 A800 上是否成立、是否需要第二级控制面项，以及系数大小均须实测，不能由 DCU 结果推断。即使满足阈值，也不直接推导所有 CUDA GPU 或所有多机拓扑的行为。

## 双卡探索结果（2026-11-09）

脚本 `experiments/f50_probe.py` 在当前单机两张 A800 上执行。分别测试默认连接数与 `CUDA_DEVICE_MAX_CONNECTIONS=1`；每种配置 200/400/800 ms 目标睡眠、两种门控、四种目的地、各 3 次有效重复，并先预热。每次 host 计时覆盖 40 个操作、每个 7 次 1 MiB 拷贝与 4 字节票据；计时不包含末尾 GPU 同步。数据见 `/root/data/stowaway-nvidia/results/raw/f50_default_validated.json` 和 `f50_conn1_validated.json` 及同名日志。

设备事件测得实际睡眠：默认配置约 197/395/789 ms；单连接配置约 160/320/640 ms。两者均随设定成比例变化，但单连接明显短于目标，故报告实际值，不把目标睡眠视为精确输入。所有配置的远端/本地**中位数**之比最大约 0.908，远端中位 host 入队约 3.0–3.4 ms，未随睡眠长度明显增加。单连接所有单次结果小于 5 ms；默认模式有一条对端 NVSHMEM 结果约 5.54 ms，其余需参考原始数据，不能声称所有单次低于 5 ms。

按预注册的同量级、40 次入队小于 5 ms 的**中位数判据**，本次双卡实验没有观察到 DCU 所述 F50 host 拉回现象；鉴于预注册未明确使用中位数且默认模式出现一次 >5 ms，本结果应标为**初步不支持 F50，不作严格通过/不通过判决**。测试没有验证多卡、跨节点、真实训练环境或其他调用方式；也不能仅凭它把规划器第二级系数设为零。需在正式目标训练载具中复核。
