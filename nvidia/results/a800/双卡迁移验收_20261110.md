# A800 双卡迁移验收记录

本记录对应单机 2×A800-SXM4-80GB、BF16 的当前 NVIDIA 迁移原型。原型使用标准 Triton、NVSHMEM Python 绑定和 CUDA stream API；并非原 Triton-Distributed 后端完整移植。原始 BW1000 仓库未修改。

## 算子

AG+GEMM、GEMM+RS、独立 RS、多缓冲复用及异步句柄均已在双卡运行。当前代码对两套载具尺寸、M=4096/8192/16384/32768 的 32 点，每点执行 8 次新输入数值对照，全部完成；每点 8 组×16 次连发的中位延迟对照中，28 点 stock/DX > 1，4 点 ≤1。逐点数据见 [双卡算子对照](双卡算子对照_20261110.md)。此为一次算子采样，不能直接当作完整模型加速。

## Megatron

- TP2/SP、小模型 DX+BRS、full recompute 三步：每卡 row/column 48、BRS layers 30，参数对照按 rtol=.02、atol=.002 通过，最大绝对差 .00048828125，日志 `/root/data/stowaway-nvidia/results/raw/tp2_final_megatron_compare_20261110.log`。
- 5120/17408 载具维度、单层、序列 4096 两步 DX+BRS 与参考参数对照通过；不是完整 Qwen3-14B 或 27B 训练。
- TP1/EP2 的 MoE NVSHMEM 原型在小模型前向、反向及 distributed optimizer 诊断运行通过；128 专家 top-8、单层短序列一轮参数对照通过。完整模型和更复杂调度未覆盖。

## vLLM

使用 vLLM 0.11 / torch 2.8，真实权重直接从共享盘读取：

| 模型 | 预填充 M | 提示×生成 token | 当前默认路径与 stock |
|---|---:|---:|---|
| Llama-3-8B | 512 | 4×48 | 输入 hash 与全部 token 一致 |
| Llama-3-70B | 1024 | 2×16 | 输入 hash 与全部 token 一致；每卡约 78 GiB |
| Qwen3-14B | 512 | 2×16 | 输入 hash 与全部 token 一致 |
| Qwen3-14B | 1024 | 4×48 | 输入 hash 与全部 token 一致 |

默认路径：列投影用 NCCL，行投影整矩阵 GEMM 后用 NVSHMEM RS；不是完整 GEMM 通信重叠，decode 等非 bucket 形状回退。分块行/列重叠在部分实际提示发生 token 分歧，只作为显式诊断选项。采样有限，不代表全部输入或服务配置均正确。

## 预测器与边界

32 点新数据上，原代价模型离线留一载具试验命中事后最快的 stock/DX 19/32；各点中位延迟之和 stock/选择/oracle 为 314.451/306.481/302.438 ms，不是端到端时间。在线规划器仍回退 stock，尚未接入 TE、Async-TP 等完整候选。

双卡能在上述受限配置下运行；完整模型训练、全形状推理、性能化 vLLM 重叠、预测器上线、TP/EP 超过 2 的通信及验证仍待完成。四卡或八卡不能仅通过修改进程数量直接运行当前 DX：runtime、peer 循环、buffer 和同步协议都限制两卡。
