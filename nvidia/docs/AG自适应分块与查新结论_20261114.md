# AG 自适应分块与相关工作查新（2026-11-14）

## 结论

**可作为 DX 的一项具体优化和论文子贡献继续研究，但不能把“根据形状自适应选择分块粒度”单独称为首创。** 在线查阅发现 Domino 在 TP 训练前基于 benchmark/grid search 确定 tensor partition granularity；CoCoPeLia 已预测 GPU 计算通信重叠并选择 tile；OverlapAdvisor 已用计算粒度与通信粒度建立统一模型，做启动时策略选择和粒度指导优化。我们的研究可以具体聚焦 *TP AG 的 peer-ready 依赖、通信/GEMM 粒度拆分、可复用缓冲的 ACK 顺序及固定外部后端的调用点补位*，能否形成有说服力的独立新颖性需要实现和进一步对照。

联网检索是有范围的查新，不可能证明没有任何论文撞车。更重要的是，2026-11-09 的 [OverlapAdvisor](https://arxiv.org/abs/2611.11857) 与“对不同重叠策略建模→按配置选择→在框架中执行→分析粒度”的大叙事高度相关；它主要处理 MoE EP、All-to-All、MoE 层级策略与 serving，我们当前聚焦 dense TP 的 AG/RS、投影调用点，以及一次固定 B 的 `{B, DX, stock}` 候选。具体问题和实现不同，不能据此保证论文完整方案无先例。若目标论文需要强化创新，应把这篇放进最近相关工作，而不是遗漏。

## 当前 DX AG 的事实

DX8 将每 rank 的 `M/8` 行发送到其余 peer，对本地输入做一次 GEMM，再依次等每个远端 peer ready，将该 peer 的 symmetric slot 复制到本地临时块，发 ACK，然后执行一次分块 GEMM。它能够边接收边计算，但产生 8 次较小 GEMM 和 7 次本地临时复制。由于 ACK 在临时副本排入当前 stream 之后发布，发送方可较早复用 symmetric slot；去掉临时复制后，如果 ACK 过早，下一轮可能覆盖仍在 GEMM 中读取的数据。

原有 99 点单卡 BF16 测试：八块 GEMM/完整 GEMM 的耗时比中位 1.173×（1.005–1.802×）。这次先测 12 个 AG 形状：ag_gu 的 2/4/8 块耗时比中位 1.000/1.030/1.186，ag_up 为 1.031/1.162/1.359；详见 [单卡 AG 粒度表](../results/a800/单卡AG分块粒度_20261114.md)。

进一步构造单卡“所有 peer 输入已就绪”的纯本地原型：原逐 peer copy+GEMM 对照相邻 peer 直接读、最多 2/4/8 个 peer 分组 GEMM，12 个形状与参考结果一致。ag_gu 的中位速度比分别 1.035×/1.082×/1.141×/1.145×，ag_up 为 1.087×/1.158×/1.226×/1.214×。这是**计算与本地复制的潜在收益**，没有跨卡通信、等待、ACK、争用或端到端；见 [单卡相邻分组原型](../results/a800/单卡AG相邻分组原型_20261114.md)。

## 研究方案：通信与计算分组分离

1. **通信仍按 peer 细粒度**：每 peer 写 symmetric slot 后发布 ready，保持已有 ring/shift 发送次序和张量分片语义。
2. **GEMM 合并相邻就绪 peer**：预先根据 rank 和发送次序构造连续 peer 行组；先处理本地 shard，再对每组中的 peer 等待 ready，使用连续 slot 构造较大 GEMM，并写到对应 rank 的输出行。组内必须是连续 rank，避免额外 reorder；shift 回环处分为两段。
3. **保护缓冲生命周期**：直接读 symmetric slot 时，把对应 peer 的 ACK 放在读取它的 GEMM 在当前 CUDA stream 上完成之后（不是 GEMM 启动前）。发送方仅在收到上一轮 ACK 后复用 slot。若使用临时复制，可在 copy 完成后发 ACK；两者的等待和内存成本需分别衡量。
4. **选择粒度**：离线基于 `(M,N,K,TP,dtype,route)` 从 `{1,2,4,8}` 选择已验证方案；不要假设已有单卡 GEMM 耗时可以预测全部跨卡重叠。组大则 GEMM 更高效，但需等更多 peer 且减小重叠窗口。
5. **逐级验证**：已有纯 CPU 分组覆盖/顺序测试；当前单卡已验证按行组输出和计算候选。下一阶段须用 2 卡先验证远端就绪、顺序、跨流 ACK、重复调用和输出保留；随后仅选少量 TP8 真实模型形状做 A/B。无 TP8 前不宣称八卡 speedup，不覆盖已验证默认路径。

`planner/original_a800/ag_grouping.py` 给出纯组计划，支持按原固定/shift 顺序、rank 排除、连续 rank 分组；`tests/test_ag_grouping.py` 有 21 项 CPU 测试。当前**尚未连接** `DirectExchange8` 的生产/实验执行路径，不宣称自适应多卡 AG 已实现。

## 建议论文定位

将论文主线保留为“固定 B 的路由选择 + DX 补位”，把以上粒度方案放在 DX 的一个可能优化，而不是把“自动调 chunk”当单独理论创新。若后续多卡验证能证明在与默认 DX 同步语义一致、包含转换开销的条件下，组方案在未见形状或实际模型中产生可复现净收益，再把其写成针对 TP AG 的具体机制贡献，并与 Domino/OverlapAdvisor 等逐项比较。当前单卡数据可用于设计动机，不应写成 GPU 间通信重叠的加速结果。
