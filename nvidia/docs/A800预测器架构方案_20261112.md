# A800 预测器架构方案（研究版，2026-11-12）

目标：对指定的一个重叠方法，在一层或同类层的各调用点选择“该方法开 / 原版”，预测它们的组合对真实训练整步或推理端到端时间的影响。不能把不同框架的算子混合为一个计划。方法候选包括 DX、Flux 等时，它们应分别得到一份独立的计划和各自的实测结果。

最新执行约束：用户不同意为四个外部仓库换 8 卡、全部编译或全量重测。Flux 和 FlashOverlap 已有实验记录，先查找并复用；其他项目先核实已有代码与数据，当前推进范围为 CPU、单卡和现有实验数据。

## 1. 分层架构

**输入与兼容性层。** 以实际模型图或框架可观测调用为准，记录调用点、层类型、M/N/K、数据类型、布局、TP、设备、拓扑、前向/重算/反向和执行频次、框架实现版本。每个后端提供自己的适配器，报告该形状与语义是否支持。未知就不启用，不把“项目支持 A800”扩大为“任意路径都支持 A800”。例如 FlashOverlap 当前 GEMM+RS 的公开实现是 FP16，Qwen BF16 和 AG 等路径需先实测或改造。

**计划分支应当一致。** 形状计划的完全相同文件和静态上下文要先在 rank 间核对；各 rank 仍须在同序调用中产生相同的标签、维度和 eligibility 判断。同一计划哈希本身不能证明动态形状或执行顺序一致；目前 NVIDIA 原型要求一个本机 world TP 组，后续多卡验证须覆盖该执行约束。

**算子层。** 对选定的方法分别估计 `stock` 和 `method` 的算子代价。原模型用单卡 GEMM、每类通信的按载荷标定曲线与重叠延迟拟合；探索模型拟合两者对数收益 `log(T_stock/T_method)` 并用按模型留一残差设保守门。具体后端可选择提供真实配置：分块数/大小、波次、计算/通信 SM、通信后端、信号/栅栏数、缓冲额外读写。未知值不虚构；训练和实际部署须使用相同来源的特征。预测的标签限定在该方法自己的实测，不使用其他方法作为该模型的标签。

**整步层。** 基准模型基于同工作负载原版整步，分别计入前向、重算和反向。对开关集合 S：

`ΔT_step(S) = Σ_i n_i·ΔT_op(i) + R(S, context)`。

`n_i` 是实际调用次数；`R` 是该方法、模型、后端与执行环境下由整步测量标定的剩余项，可表示启动、资源争用、上下文、回退等合并影响。它是**剩余值，不自动代表 CPU 控制面因果**。在数据足够时，可尝试 `R = Σ r_i x_i + Σ r_ij x_i x_j` 并与低复杂度基线比较；在没有相应观测时，不推断单个点或交互。独立 BRS 与四个投影开关分离，避免对前反向改写重复计数。

**组合层。** 对指定方法枚举可执行的二进制开关，最多四点是 16 种；混合注意力有多类层时，按实际层类型区分并计算计数。更大搜索空间可以引入约束或剪枝，但不能事先把某种方法的最佳 tile 当作全局通用规则。当前 `combination_planner.py` 默认仅选择实际测过的组合；可选线性模型外推受可辨识性检查，明确是研究选项，未验证。

**输出与回退。** 写入模型和实现的版本、平台和 TP、操作语义、各调用点选择、标定数据摘要、可用性、预测时间、误差/支持范围。部署时确认全部 rank 使用相同计划；不兼容时整组回退 stock，避免 rank 分歧导致死锁。推理、训练以及不同长度的形状各自确认，不能将推理第一级计划直接称为训练整步计划。

## 2. 和四个仓库的关系

| 系统 | 可借鉴输入与机制 | 能否直接作为 Qwen BF16 TP8 训练四开关后端 |
|---|---|---|
| DX | 分块 cuBLAS GEMM、每 peer 发送/票据、RS 归约，前向和行反向等路径不同 | NVIDIA 原型已有覆盖但训练预测器还未标定；完整长训/实权重未证明。 |
| Flux | CUTLASS tile、通信流或 epilogue、形状与拓扑的调优配置 | README 有 sm80、AG 与 RS；本环境、BF16 训练前反向与具体接口未验证。 |
| FlashOverlap | wave 分组、计算资源占用、带宽曲线的预测搜索 | A800 支持明确；公开 RS 路径是 FP16，AG 和 BF16、训练整图接入未验证。 |
| Triton-distributed | 通信分块、SM 划分、tile swizzle 和设备同步 | 需固定具体内核与编译版本、验证 A800 路径及前反向集成。 |
| Syncopate | chunk 与依赖描述、可换传输后端、波次和 SM 调参 | 论文测试 Hopper；示例有 TMA，A800 是否支持选定路径待验证。 |

具体源码与首次结果持续记录于 `重叠系统与预测器研究日志.md`。四个项目本身已经做过不同层次的重叠调优；本方案的潜在研究价值在于**一个后端内部、按实际计算图选择端到端组合并量化代价与泛化**，是否有充分新颖性和优越性需进一步与论文原文及实验对照，不能预先保证。

论文贡献还需遵守原仓库的边界：`docs/论文1与论文2差异分析.md` 明确认为 DX 的推送、票据和槽位协议继承论文 1，也已有相关先例；不能仅因将其与预测器组合就宣称这套协议是论文 2 的全新独立贡献。可以把适用于厂商 GEMM、训练前反向及 A800 的 DX 实现作为系统组成，潜在新贡献应由具体新机制、证据和相关工作对比决定。

## 3. 当前可交付和缺口

- 已有 DX 99 点是 A800 8 卡、16 连发及单次的算子测试，可复用；另有 99 点单卡分块探针。新相对模型达到 88/99、1.062×，但有一个比原版慢 10.34% 的点，是探索结果，不替换原模型。
- 已有 Llama3-70B vLLM 推理 Plan 真实跑过；Qwen3.6 使用文本混合注意力载具、随机权重和 mock 数据。它与旧 dense 27B 不同，不能用 dense 形状公式假装完整 Qwen3.6 调用点。
- Qwen 的 MBS2、MBS4 完整行前反向＋BRS 和四处开已有数据，但不同开关/批次并不齐全；不能从两处一起开的测量推出每一处的收益。GPU 换回多卡后，只补能够区分关键开关、方法与整步交互的数据，不重做已有点。
- 预测器需支持真实训练图的 Qwen 混合层和各路径频次，并在 8 卡重新实测其计划；当前整步原型尚未接 Megatron。其他系统既无本环境性能标定也无 E2E 接入，不能宣称已支持。

## 4. 当前代码入口

- `planner/original_a800/relative_model.py`：单一后端的相对收益探索模型；已有结果不能替换生产 cost model。
- `planner/original_a800/combination_planner.py`：同一后端内的组合选择，默认只选已经实测过的开关组合；显式外推才允许使用假设模型。
- `planner/original_a800/qwen36_shapes.py`、`qwen36_plan.py`：按 Qwen3.6 GDN、完整注意力和 MLP 的真实形状生成算子级探索结果，输出注明范围外推和非端到端。
- `stowaway_nvidia/shape_plan.py` 与 `experiments/megatron_prelude.py`：显式的 TP8 DX 形状计划诊断入口。计划包含平台、PyTorch、Triton、CUDA、调度、反向和 BRS 参数；所有 rank 校验摘要一致后才加载。缺少精确条目回退 stock。它尚未接入 Qwen 的生产计划，也没有替代 A800 第二级整步标定。
