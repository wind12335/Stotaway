# Stotaway 原版与 NVIDIA 预测器对照（2026-11-13）

## 目标和事实

两者核心目标相同：在同一重叠方法内，为 QKV、o_proj、fc1、fc2 等调用点选择重叠或 stock，避免把算子级优势直接等同于整步优势。NVIDIA 分支扩展了后端路径描述、预测建模和部署接口，但目前是多条实验原型，不是所有原版能力均完成替换的一个成品。原版是 BW1000 标定和验证；A800 不可直接复用其时间系数或控制面规律。

| 方面 | BW1000 原版 | NVIDIA 当前实现与成熟度 |
|---|---|---|
| 算子级模型 | `planner/costmodel.py` 根据 G、通信字节、op 拟合 stock、DX 和拆批候选，训练误差分位数与 2% 安全门；16 连发。 | 按实际 route 拟合收益，探索 shape-only、G/C、分块损失和 reduced probe 模型；均为不同实验候选，不是每个都更优。当前 reduced 模型无原版那样的误差分位数安全门。 |
| 整步 | `planner/planner.py` 枚举 AG 子集，利用 BW1000 层周期和控制面项估计整步影响；RS 独立阈值在原仓库最新交接中明确是占位值。推理跳过训练整步模型。 | `unified_step.py` 按调用次数和相同 workload 的整步残差/交互做组合；已有随机 mock 训练诊断，目标 workload 整步标定参与拟合，尚未证明未知整步泛化。不能把 BW1000 F50 当 A800 定律。 |
| 计算/通信后端 | 针对自己的 BW1000 DX/RCCL 及设备数据；切批候选已建模但训练执行未接入。 | `predictor_registry.py` 显式区分计算、传输、对称内存、同步、实际路径与硬件软件；已识别 DX、FlashOverlap、Triton-distributed 的部分具体路径，Syncopate GPU 路径未验证，不自动解析任意源码。|
| 训练数据隔离 | 按原仓库载具及平台标定和留出实验。 | route、TP、dtype、软件和计时口径分开；新 reduced 模型拟合时对通信/stock 估计按物理族交叉拟合；不能把不同后端或版本的参数混用。|
| 目标采样 | 通常单卡 full GEMM + 预标定通信曲线。 | reduced 模型需目标 full/split GEMM 两项；每项可取 2 个 16 连发样本，需将采样成本算入收益，且尚未证明 2 样本适用于所有形状。|
| 输出和执行 | 命令行给出调用点方案，原执行脚本配置使用。 | 支持 JSON 模型/查表/计划、环境与形状校验、两个 rank 校验摘要和工作负载、未知形状回退 stock；合成双卡实测、Megatron mock、vLLM 真实模型验证程度不同，不能统称全部上线。|
| 动态运行 | 训练前离线决策为主。 | 已有预列形状的集体预测与缓存原型，动态安全点接口可用；不是已自动识别所有动态 shape，也不是 CUDA graph 内即时预测。|

在上述 reduced 模型之上新增同 route、同 AG/RS 的邻近物理族留出残差修正：只利用目标 full/split GEMM，不用目标 stock/DX 时间。vLLM 环境两组各 32 个新的合成物理点、每组一次独立复测，第一组 local 29/32、1.1147× / 29/32、1.1111×，基础模型 26/32、1.1076× / 26/32、1.1017×；第二组 local 28/32、1.1091× / 27/32、1.1155×，基础模型 27/32、1.1102× / 28/32、1.1248×。两次是同形状重复，并非 128 个独立点；局部修正并非每组都更好，未计采样成本。这是候选算法结果，不证明普遍优势。

扩充训练后冻结模型和新一组 32 点，首先采两项 GEMM 并冻结选择，再测目标 stock/DX；两批分别 **27/32、1.1176×、1 慢点**和 **29/32、1.1256×、1 慢点**，均为同一批物理点的独立测量。事后对照原训练集模型的选择完全一致，不能归功于训练集扩充；在等频调用的示例中还需 6.407 秒组件采样且相对总用 DX 没有回本点。不能用几何平均替代整模型耗时或成本。

FlashOverlap 和 Triton-distributed 已在双卡分别接通各自 stock/重叠选路；FlashOverlap 的五个旧复测点跨批次留族只对 1/5，事后同形状分位门 5/5（并不检验未知形状），Triton-distributed 仅有三个旧形状的额外复测。Flux 的用户 4 卡资料可做离线小样本回放，但无法确认与本机环境等价；Syncopate 尚无 A800 GPU 性能数据和 E2E 验证。当前并非四个外部系统都已完整适配。

## 当前可得出的结果

在 A800 TP2、BF16、PyTorch 2.7 环境，冻结的 reduced 模型针对 v6 新族两批 33/40、1.0972× / 1.0979×；v7 新族两批 31/40、1.1032× / 32/40、1.1067×，两批是相同形状复测。每批包括正确选择 stock 的点，slow 点分别 5/4 与 7/6，几何平均没有包含目标采样成本。它支持前向算子有效性，不说明全模型、所有形状或多后端均达 80%。

稳定性与收益存在取舍：基于已查看的 v6/v7 数据事后尝试预测收益门槛（非盲测），0.02 的 log 收益门槛在 v7 两批中分别把慢点从 7/6 减至 5/4，但 v6 准确率由 33/40 变为 32/40；0.05 更保守、慢点更少，也漏掉更多收益。旧 72 点族外预测上 0.02 为 57/72、8 慢点，相比无门槛 58/72、9 慢点。没有独立样本确定其稳定优势，暂不替换线上决策规则。

同 vLLM 环境的 48 个开发点，嵌套物理族留出、训练折内选门槛的结果为 34/48、1.0884×、9 慢点，与零门槛完全相同；门槛候选虽然因折不同而变化，却没有改变外层被留出点的决定。该尝试未带来实证提升，不接入默认规则。

PyTorch 2.8/CUDA 12.8 vLLM 环境中，3 个训练载具族的 reduced 模型对 Llama70B M1024 的首次算子样本为 1/4、1.0738×、2 慢点；扩充为 6 个非目标载具族后冻结 v2，后续相同 Llama 形状两批为 3/4、1.0511×、0 慢点与 4/4、1.0537×、0 慢点。前一批的 Llama 结果已经被观察，v2 不能称作全新目标盲测；这四点不代表全模型，也不含采样成本。

真实 Llama3-70B 权重的 vLLM TP2 测试已运行：batch 4、输出 32 token，计划相对上游 stock 的两组速度比为 1.0010×/0.9999×；相对同 SP 适配器 stock 为 1.0059×/1.0078×，token 一致。两组很少且没有扣启动与采样成本。Qwen3.6 的 Triton 3.3 匹配计划在四层随机 mock 训练中两组为 1.0019×/1.0013×，不是真实完整 27B 训练。现有 JSON 必须与 GPU/TP/BF16/PyTorch/Triton/CUDA/连接设置和具体 M/K/N 匹配；旧模型缺拓扑签名，需确认机器拓扑并在跨环境时重新标定。

## 判断

新版在架构表达与工程接口上有明确扩展，在 DX 前向未见形状和真实 Llama 执行上有初步结果；并未证明所有后端、整步和未知场景都优于原版，也无法承诺所有形状或 E2E 都正加速。下一步优先处理跨独立进程的状态波动、标定代价、目标 workload 下的整步可迁移性，按各个后端及 TP 分开验证，不混合不同方法。
