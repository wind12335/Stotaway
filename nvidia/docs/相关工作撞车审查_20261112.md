# 后端族预测器与重叠方法：相关工作撞车审查

记录时间：2026-11-12。本审查基于已有本地论文全文与源码，外网 OpenAlex、arXiv 通过用户指定代理的 TLS 握手失败；因此不是穷尽检索，尚不能证明不存在其他先例。下述“差异”是当前可观察的范围差异，不等于已证明新颖。

### 对 FlashOverlap 源码的直接核实

`/root/FlashOverlap/tune/search.py` 的 `predict_lat` 按 wave group 递推累计计算与通信时间，通信侧使用 `max(acc_comp_dur, acc_comm_dur) + comm_dur`，并依据通信带宽插值、SM 预留和 GEMM wave 数估算开销；下面的搜索枚举分组、按估计延迟选候选再实际运行。因此本仓库 `pipeline_subset.py` 的 producer/consumer 双资源 `max` 递推与它的核心形式明显重合，必须当作已知模型结构而不是预测器新算法。我们的候选差异在跨固定方法的适配接口和整步调用点组合；这仍需要独立核查先例与实验，不能由此自动推出新颖性。

## 当前合理的贡献假设

在**固定一种重叠方法**的前提下，研究一套可接入不同实现的规划接口：以实际执行签名隔离硬件/版本/方向/配置，结合该方法自身的算子预测、真实前向/反向调用次数及整步交互校准，选择调用点的开关；同时提供 DX 实现。这是可验证的系统组合假设，**不是已确认首创**。须特别核实 Centauri、Mercury 及其他图规划工作。

单独这些要素均不可声称新颖：pipeline 递推、预测重叠代价、自动调优、按 workload 改调度、标准 GEMM + DMA、fallback stock，以及测得所有点至少 1.00×。若某项机制能证明此前工作没有并且在跨后端、低标定成本、训练整步效果上有显著增益，才能进一步讨论创新程度。

## 必须保留的证据界限

1. 每套方法单独决策，不能把一个调用点用 Flux、另一个调用点用 FlashOverlap。
2. 4 卡 FP16 用户日志不含已确认的 GPU 和拓扑，不能用于冒充 A800 TP8 BF16 标定；两族的实现参数不能混用。
3. A800 99 点 16 连发是离线、按模型留一的算子选择评估；现有数据已参与开发，不能当独立最终测试或训练 E2E 准确率。
4. 若选择 stock，理论上预测的相对速度是 1.00×；真实独立测试仍有测量噪声和运行时开销，不能保证所有场景不回退或严格加速。
5. 全文未核实的工作列为待查，而不是推断其不支持 E2E。未获得独立评测前不声称达到 80% E2E 选择准确率或 CCF-A 水平。
