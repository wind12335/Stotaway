# 八卡实验方案与基线可行性（2026-11-13）

## 当前判断

用户拟定的方向是合理的：多模型投影 MNK 的 AG+GEMM、GEMM+RS 算子测试，加 Llama3-70B 推理及 Qwen3.6-27B 训练端到端，并比较现有重叠技术。现阶段可以准备并安排 **TP8 预检和探索性标定**；不能把整个系统和全部基线都标成已适合正式大规模测量。已有 TP2 实验、TP8 数据、用户给出的 4 卡 Flux/FlashOverlap 记录保持原样，不因新增方案重跑。

最新目标：每次指定一个已有重叠后端，定位其低效调用点，在能力和兼容性满足时选择 DX 补位；其余位置保留已有后端或使用 stock。一个方案最多包含该指定外部后端、DX 和 stock，不把 Flux、FlashOverlap 等多个外部后端组合到同一方案。原先同方法二选一实验仍是有效基线，现有代码尚未完成外部后端+DX 的实际组合执行。

## 8 卡执行次序

1. **先做节省卡时的预检**：确认独占性、GPU 拓扑、驱动、NCCL、NVSHMEM、P2P，运行 DX、Async-TP、Triton-distributed 的 TP8 小形状正确性；FlashOverlap/Flux/Syncopate 只按已有入口最小化验证。记录每个方法的实际 kernel 路径、版本、dtype、可支持的 collective，失败原样记录。
2. **算子实验**：依据真实 Llama/Qwen 投影提取 TP8 的本地 M/N/K、dtype 和前后向语义，先固定覆盖清单、训练/留出物理族与测量协议。在支持的相同 AG 或 RS 上比较 stock、指定外部后端、DX 及其预测补位选择；统一同步和统计口径，保留用户要求的每个样本 16 次连发，并报告多次独立进程重复。记录探测/搜索/编译成本，未支持的组合不记作 1×。
3. **预测器**：TP8 单独训练或标定。对每个指定外部后端分别验证外部后端+DX+stock 的候选能力和兼容性；保留按物理族留出、冻结后测标签、重复批次；统计相对原外部后端和 stock 的净耗时、正确率、标定开销和回本。scratch 为独立路径，不读取原 DX 计划。
4. **推理 E2E**：Llama3-70B 的 vLLM 以一致权重/tokenizer、prompt、实际上下文、batch、输出、dtype 和 TP8 对比 stock、DX、DX+plan；Async-TP/FlashOverlap 仅在实现确实接入并命中后加入。Triton-dist 独立推理引擎可作为系统级附加对照，需单独说明执行引擎/调度差异。推理分别报告 prefill、decode、TTFT、吞吐、显存、端到端含和不含一次性标定成本，并检查数值或输出质量；不把 token 必须逐位相同设为唯一准入条件。
5. **训练 E2E**：以 Qwen3.6-27B 实际 64 层配置、明确数据、MBS/GBS/seq/recompute/optimizer、TP8 运行真实前后向和优化器；比较 stock、DX、DX+plan，与已验证可用的 Async-TP/FlashOverlap 等。记录 warmup、稳态 step time、tokens/s、显存、loss/梯度有限及可复现性，分开报告一次性编译/标定成本。不能将随机四层 mock 当真实 27B 训练。
6. **正式数据锁定**：先确定允许的运行次数、形状和执行顺序，冻结预测器/参数，再采独立评估。报告所有失败和退化，独立进程为重复单位，避免把 16 连发当 16 次独立实验。留出工作负载若已参与调参，应明确标作开发或复测。

## 创新定位和风险

当前可研究的贡献假设：为指定外部后端检测低效调用点，并在兼容性与净成本约束下使用 DX 补位，优化整个工作负载。该跨外部后端与 DX 的执行闭环尚待实现；新 scratch 目前只证明部分 TP2 形状/小型训练载具可用。FlashOverlap predictive search、FiCCO 特征选择、Syncopate 后端与 chunk 自动调优及 Flux 本身已有重叠机制，不能直接声称各组件首创。参见 `相关工作撞车审查_20261112.md`，其中旧的同方法定位需按本次更新重新核查先例。

## 8 卡资源使用建议

如果能获得 8 卡，建议先申请足以完成预检和最小标定的短时段；预检有可运行数据后，再扩展正式矩阵。当前尚不能预估四个外部仓库全部编译/适配与完整两模型 E2E 的总卡时，尤其不保证每个方法都能在 A800 上完成相同 E2E。数据落盘目录 `/root/data/stowaway-nvidia/results` 可写，但剩余约 25GB，避免重复下载 70B 模型和不必要参数捕获。
