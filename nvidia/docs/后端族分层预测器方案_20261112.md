# CUDA/CUTLASS 与 Triton 后端族分层预测器

## 结论

可以把预测器分为 CUDA/CUTLASS 和 Triton 两个后端族，让它们分别识别并预测计算通信重叠方法。但“后端族”只能是第一层路由，不能代替具体实现的代价模型：Flux、FlashOverlap、Triton-distributed、Syncopate 和 DX 的通信协议、分块、SM 使用和回退路径不同，必须保留各自的实现签名和标定参数。

预测器的输出仍然遵循当前约束：一次固定一个重叠方法，在这个方法内部决定 QKV、o_proj、fc1、fc2 或 Qwen GDN/MLP 真实逻辑点开不开，以及该方法自己的 kernel 配置。不会在一个计划里混合选择 Flux、FlashOverlap 和 Triton-distributed。

## 后端族归类

| 后端族 | 项目或路径 | 计算通信特点 | 预测时必须保留的差异 |
|---|---|---|---|
| CUDA/CUTLASS | Flux | CUTLASS GEMM 与 copy engine/epilogue 组合，依赖编译期 tile 和运行时配置 | CUTLASS hparams、tile、stage、ring mode、world/topology、通信配置、是否命中注册表 |
| CUDA/CUTLASS | FlashOverlap | CUTLASS GEMM、NCCL、wave group、计数等待 kernel；已有带宽曲线和 predictive search | BM/BN/BK、tile waves、group partition、通信带宽曲线、SM 预留、AR/RS、边界 tile 可用性 |
| Triton | Triton-distributed | Triton producer/consumer、NVSHMEM signal、tile swizzle、compute/communication SM 划分 | Triton-distributed/Triton 版本、persistent 条件、tile/config、NUM_SMS、comm SM、signal/barrier、small GEMM fallback |
| Triton | Syncopate | Triton source transform、chunk dependency graph、多种 communication backend、chunk/SM/tile autotune | compiler/transform 版本、chunk shape/split、backend、dependency/signal 数、copy/compute SM、TMA 可用性 |
| 混合实现 | 当前 DX NVIDIA 原型 | GEMM 主要调用 `torch.matmul`，Triton 做信号与归约，NVSHMEM 做对称缓冲；不是 CUTLASS fused GEMM，也不是完整 Triton GEMM | vendor GEMM 类型、分块 GEMM 损耗、peer 顺序、ACK、NVSHMEM、前/反向路径、BRS 命中和 fallback |

DX 不能强行归入其中一族。更准确的标签是：`compute=vendor_gemm`、`control=triton`、`comm=nvshmem/cuda-copy`。如果将来把 DX 的 GEMM 改成 CUTLASS，才生成新的 CUDA/CUTLASS 实现签名，不能沿用当前 DX 参数。

## 分层结构

### 1. 执行签名路由

每个候选实现带有不可省略的 `BackendSignature`：

```text
family: cutlass_cuda | triton | hybrid_vendor_triton
compute_backend: cutlass | triton_dot | torch_vendor_gemm
communication: nccl | nvshmem | cuda_copy | tma | sm_load_store
compiler_version: CUDA/CUTLASS 或 Triton 版本
arch: sm80 等
dtype: fp16/bf16
tp/world/topology
direction: ag | rs | ar | a2a
schedule: wave/chunk/peer order
config: tile、stages、waves、chunks、compute_sms、comm_sms、signals
fallback_path: none | vendor_gemm_plus_collective | unsupported
```

路由首先检查实现是否支持当前 `(arch, dtype, shape, direction, phase)`。缺少支持证据、配置未命中、边界 tile 不可处理或运行时会回退时，候选标成不可用；预测器返回 stock。预测器不能从一个项目的 timing 反推出另一个项目的签名。

### 2. 后端族内配置选择

在固定一个实现之后，再选择该实现自己的配置。例如：

- CUDA/CUTLASS：在可用的 CUTLASS tile、stage、ring/wave 配置中选择；FlashOverlap 的 wave grouping 属于这一层。
- Triton：在 persistent/non-persistent、tile、chunk、SM 分配和 signal schedule 中选择；Syncopate 的 backend/chunk/tile 搜索属于这一层。
- DX：在 peer 顺序、ACK 合并、分块方式和前/反向 context 中选择。

这一层的预测目标是一个具体配置的调用代价，不是整个后端族的平均速度。

### 3. 调用点开关选择

对每一个真实调用点设置二进制变量 `x_s`：

```text
x_s = 1：该调用点使用当前固定后端及其选定配置
x_s = 0：该调用点使用 stock
```

Qwen3.6 需要按 `(layer_type, site_name, M, K, N)` 区分 GDN 与 MLP。不能因为二者都叫 `fc1` 或 `fc2` 就共享一个预测标签。

### 4. 整步组合选择

对训练或推理图中的实际调用次数进行展开：

```text
Delta_step(x) = sum_i count_i * Delta_op_i(x_site(i))
                 + H_backend(context, x)
                 + sum_(s,t) J_st * x_s * x_t
```

`H_backend` 和 `J_st` 只用同一个后端、同一个平台、同一个 dtype、同一个 workload 的整步数据标定。没有整步数据时，只输出算子级探索计划，不能称为 E2E 最优计划。

## 两族的共同模型和不同模型

两族可以共享一个**物理结构**：对 AG、RS、AR 采用 producer/consumer chunk pipeline：

```text
P_j = P_(j-1) + producer_chunk_j
C_j = max(C_(j-1), P_j) + consumer_chunk_j
T_pipeline = C_last
```

但 `producer_chunk_j`、`consumer_chunk_j` 的生成方式必须族内实现：

- CUDA/CUTLASS 使用 CUTLASS tile、NCCL/copy-engine、wave group 和编译期配置。
- Triton 使用 Triton tile、chunk dependency、signal/barrier、persistent 条件和 SM 分配。
- 混合 DX 使用 vendor GEMM 的分块测量、NVSHMEM 对称槽、peer 序和 ACK。

可共享的是参数命名和验证框架，不能共享未经校准的系数。相同 `M/K/N` 在不同后端中不代表相同 `T_pipeline`。

## 已有四卡数据如何使用

用户提供的四份记录均为 4 卡、FP16：Flux AG/RS 和 FlashOverlap AR/RS。它们适合做两件事：

1. 验证“固定某个方法后，预测器会根据 shape/direction 选择开或关”的算法流程。
2. 为 CUDA/CUTLASS 族的历史 shape 建立方法内示例，保留失败、边界和速度波动。

它们不能直接用于 A800 TP8 BF16 的训练模型，也不能和 A800 DX 99 点合并拟合。当前整理结果中，FlashOverlap RS 的三个独立 shape 由算法选对 3/3，但样本不足以证明泛化；FlashOverlap AR 只有两个独立 shape；Flux AG 每个 shape 只有一次 invocation。

## 安全边界

- 不把 CUDA/CUTLASS 和 Triton 记录混合训练一个回归器。
- 不把仓库名称当作实际执行路径；必须记录是否 fallback 到 vendor GEMM/NCCL。
- 不把算子级选择率当作 E2E 正确率。
- 不把 4 卡 FP16 结果迁移成 A800 TP8 BF16 系数。
- 不在没有整步组合观测时声称 Qwen 训练或 Llama 推理已经找到最优开关组合。
- 不需要为了完成这套 CPU/历史数据算法验证而申请 8 卡；最多两卡只能验证通信协议或小形状路径，不能证明 TP8 泛化。

## 当前实现状态

- `planner/original_a800/pipeline_subset.py`：producer/consumer 递推、非负残差拟合和固定单后端组合枚举。
- `planner/original_a800/extract_reference_pdfs.py`：四份 4 卡 PDF 记录抽取、失败记录和 SHA256 provenance。
- `planner/original_a800/validate_pdf_pipeline.py`：FlashOverlap RS 的 CPU 留一 shape 探索，3/3；不作泛化结论。
- `planner/original_a800/combination_planner.py`：同后端整步组合观测的实测优先选择和可选外推。
- `stowaway_nvidia/shape_plan.py`：DX TP8 形状计划的显式运行时校验和 stock fallback。

因此，答案是：**可以分为 CUDA/CUTLASS 和 Triton 两个主要计算族，并让预测器识别、预测两族；但 DX 需要作为混合族单独建模。**这套分层算法已经可以用现有四卡记录和 CPU 验证，暂时没有申请 8 卡的理由。
