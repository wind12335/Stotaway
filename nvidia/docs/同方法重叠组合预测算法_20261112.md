# 同一重叠方法的组合预测算法（2026-11-12，研究原型）

本算法一次固定一个方法（DX、Flux、FlashOverlap、Triton-distributed 或 Syncopate 中的一个），输出各调用点开/关；**不跨方法混用**。QKV、o_proj、fc1、fc2 是常见的四个开关；Qwen 混合模型中 GDN 与 MLP 同名但形状不同，应拆成真实调用点，若实现只能一起开则用联动约束合并。

用户提出的 CUDA/CUTLASS 与 Triton 两族路由方案见 `后端族分层预测器方案_20261112.md`；当前 DX 是 vendor GEMM + Triton 信号/归约 + NVSHMEM 的混合实现，应单独签名，不强塞到任一族。

## 一、明确研究问题

现有 Flux/FlashOverlap 四卡记录说明，重叠方法对不同算子形状可能赢或输，见 `四卡既有实验整理_20261112.md`。已有 A800 DX 99 点和 Qwen 训练记录表明算子与整步的收益不能直接等同。目标是根据**一个给定重叠实现**、模型图和平台信息，预测整个训练步或推理工作负载中哪些位置应该启用它，最大化预测的总收益，并对未知实现/环境回退。

现有 Flux、FlashOverlap 四卡数据是独立算子记录，不含一个模型的开关组合及整步时间；不能从它们算出 E2E 选择正确率。也不能用四卡 FP16 的系数直接作为 A800 八卡 BF16 系数。

## 二、输入与可用性

对每一个实际调用 i 记录：`site, phase, op, M, N, K, dtype, TP, count`，其中 phase 是前向、重算、dgrad、wgrad 或独立 RS；count 是每步/每请求真实次数。还输入指定实现 b 的版本、设备与拓扑、数据搬运后端、每块先后顺序、chunk 粒度、计算/通信 SM 和 signal 信息，以及单卡 GEMM、已有同平台通信/重叠标定、可用的整步测量。

实施前按实现核对算子、方向、dtype、尺寸、layout、设备、版本、训练反向是否支持。如果缺少支持证据，`eligible=false`，该调用点回退 stock。FlashOverlap 的当前 RS 调优存在 N/BN 边界断言，记录中 N29568、BN256 的搜索失败；故应以具体候选 tile 的整除条件过滤，而不是把该形状的失败当作性能数字或理论限制。

## 三、算子级：按依赖预测重叠时间

对候选的一个分块方案，建立各 chunk 的生产与消费时间 `p_j, c_j`，单位 ms：

```
P_0 = C_0 = 0
P_j = P_(j-1) + p_j
C_j = max(C_(j-1), P_j) + c_j
T_pipeline = C_J
```

AG：生产者是通信，消费者是 GEMM；RS/AR：生产者是 GEMM，消费者是通信。这是两个串行资源、相同 chunk 顺序、可跨资源重叠的简化模型。对真正的复杂图、多 SM 竞争、多个 streams 或不同 rank 顺序，它只是近似，需用后端特定测量修正；不假设它和每个工程实现逐指令等价。

对于 DX 可以使用已有的 8 块 GEMM 时间、传输时间、信号/等待数；Flux 按其具体 GEMM tile/通信方案提供对应信息；FlashOverlap 可直接使用其已有 wave grouping 和带宽曲线，避免重复发明其 `predict_lat`；Triton-distributed 和 Syncopate 从各自 chunk/SM/依赖配置取得信息。所有阶段代价必须来自对应后端与平台：没有就标记未知，不能用其它后端或 TP 的参数伪装。

计算干扰和固定开销项，用真实标定拟合或验证，不默认为零：

```
T_overlap_hat = T_pipeline + H_launch_sync + H_resource + H_tail
T_stock_hat   = G_full + C_collective + H_stock
Δ_i           = T_overlap_hat - T_stock_hat
```

若只有聚合算子数据，而没有 chunk 参数，则沿用原 cost model 或相对收益模型，**不凭形状猜测 p/c**。特征包括真实分块 GEMM 效率、payload、G/C、对齐、tile/wave、信号次数、通信占用等；可按数据量逐项启用。当前单卡分块特征虽然与 DX speedup 相关，但放入现有相对模型后 16 连发从 88/99 下降到 85/99，故现阶段不默认使用。

## 四、整步级：枚举同一种方法的调用点组合

令 `x_s ∈ {0,1}` 是一个实现的调用点 s 的开关。每个真实调用 i 从属于某个 site，已测或预测的 `Δ_i` 包含这个具体 phase 的开销。加法基础与整步修正：

```
ΔT_hat(x) = Σ_i count_i × x_site(i) × Δ_i
          + H_context × 1[任一开关启用]
          + Σ_(s<t) J_st × x_s × x_t
```

`H_context` 是上下文的一次性整步残差（不等同初始化时延）；`J_st` 是该组合的整步交互项。它们由**同实现、同平台、同目标、同批次**的实测整步标定；数据不足不能当作已知零，也不能把 BW1000 F50 直接用于 A800。不同阶段可用不同算子代价，保证不把一个前向算子收益重复当成完整反向收益。独立 BRS 是单独开关；Qwen 中同一个适配器名称对应的不同层要有独立形状/计数。

对于四个二进制开关最多 16 个组合，直接枚举；约束过滤不支持、必须联动、超显存及计划执行不一致的组合。在多于四点时可以枚举可部署组合或分组，而不是强行混合不同后端。

## 五、误差控制和选择

在训练集按模型或工作负载分组留一，构造每个 site/phase 的过度乐观误差上界 `u_i`。它是经验校准量，不是保证：

```
score(x) = ΔT_hat(x) + Σ_i count_i × x_site(i) × u_i + u_step(x)
choose = argmin_x score(x)
```

若 `score(best) >= -margin_step`，选择全 stock；模型外推、缺少整步标定或缺少某个 phase 的条件下，默认回退，或只生成带“研究外推”标记的候选。误差过于保守会错过收益；用留一正确率、几何平均 speedup、相对已测最优损失及落后 stock 的个数共同评价，不要求每个点完全预测对。

具体代码 `planner/original_a800/pipeline_subset.py` 实现了块依赖递推与单后端组合枚举：外部必须传入 `T_stock/T_overlap/count`、整步残差和安全门。它不把缺失的标定填成实测，也未自动接入训练；现有 `combination_planner.py` 则可在有同上下文整步观测时限制选择可辨识/实测组合。兩者均是研究原型，数据不足时不能自动得到完整 Qwen Plan。

## 六、如何以已有数据检验

1. 已完成：DX A800 99 点（16 连发）11 模型留一；原模型 86/99、1.057×，相对收益探索模型 88/99、1.062×但有 1 个 10.34% 退化点。均为前向算子数据，不能称整步。
2. 已完成：Flux 4 卡 AG 5 个形状、RS 7 个形状与 FlashOverlap 4 卡 5 组不同形状的记录整理。Flux 的每个 shape 是一次运行，四个 rank 不算重复；FlashOverlap 每个 shape 两到五次 invocation，含 1.1185× 的异常变化完整保留。使用其作同后端、同口径算子选择的探索数据，不与 TP8 DX 合并训练。
3. 尚缺：每个实现的 phase/step 参数和可部署模型 E2E 组合标签。现有 Qwen fbag/fbc 还混合 BRS 和不完全相同窗口，不能从一组结果拆出所有单独开关的交互。现有 Llama3-70B 仅做推理，Qwen3.6-27B 用于训练。
4. 后续仅若用户同意，最多两卡做小规模机制验证；TP2 无法证明 TP8 的性能。不申请 8 卡、不编译四个仓库、不重新测用户已有结果。先用已有数据完成代码和算法验证。

## 七、与相关工作区别和创新边界

Flux 做 kernel 融合及配置调优，FlashOverlap 已有按带宽和 wave 的预测性分组搜索，Triton-distributed 具备分布式 kernel 与 auto-tune，Syncopate 按 chunk/backend/SM 进行搜索。因此块流水线递推、分块、SM 调优不是本方案独有的新发现。可检验的系统贡献方向是：**在固定实现内部，把独立算子可用性、前反向调用图和整步残差结合，选择整组开关，并量化误选成本和低代价标定**。是否构成充分论文创新，要在对应文献和可复现 E2E 结果支持后判断；不能承诺全局最优或 CCF A。

## 八、基于现有四卡记录的具体验证

现有 PDF 记录已经结构化为 `planner/original_a800/data/reference_pdf_records.json`：Flux AG 5 个形状、Flux RS 7 个形状、FlashOverlap AR 2 个形状、FlashOverlap RS 3 个形状；全部是用户确认的 4 卡，FP16，GPU 型号和拓扑未写明。Flux AG 每个形状只有一次 invocation，四个 rank 是同一执行的不同参与者；FlashOverlap 多次 invocation 才能计算中位数。

FlashOverlap RS 的三种独立形状为：

| 形状 M/N/K | stock 中位 ms | overlap 中位 ms | 实测 speedup | 算法选择 |
|---|---:|---:|---:|---|
| 8192/49152/12288 | 40.961 | 42.291 | 0.969× | stock |
| 8192/53248/16384 | 58.896 | 60.042 | 0.981× | stock |
| 16384/29568/8192 | 35.900 | 33.928 | 1.058× | overlap |

用固定 J=4 的粗粒度 producer/consumer pipeline 特征、留一形状拟合非负 scale/fixed residual 和 80% 训练残差安全门，算法在这 3 个形状上选对 **3/3**。这只是同一记录集上的探索结果，样本只有 3 个，不能称泛化验证；AR 只有 2 个不同形状，暂不做留一结论。FlashOverlap 的 AR/RS 搜索失败和 RS 1.1185× 的单次异常均保留为可用性/噪声证据，不被删除或当成稳定收益。

因此，算法已经具备一个不依赖 8 卡的验证闭环：用已有四卡记录检查“固定一个后端 → 预测开/关 → 与同形状实测最优比较”。它还没有证明 A800 TP8 的性能，也没有产生 Qwen 训练 E2E 结论；这两项需要另外的数据和明确授权。
