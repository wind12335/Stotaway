# 系统原理与八卡完成标准（2026-11-13）

## 用户最终确认的八卡实验顺序与范围

严格按此顺序：**① 多模型 MNK 算子 → ② Qwen3.6-27B 的 Megatron 训练端到端 → ③ Llama3-70B 的 vLLM 推理端到端 → ④ 汇总和预测器评估**。对比方法为 Async-TP、FlashOverlap、Triton-distributed、Syncopate 和 DX；以对应配置的 stock（GEMM 与 NCCL 顺序执行）作为 1.00×，所有速度比为同配置 stock 耗时 / 对应方法耗时。对于每个固定的外部后端 B，补位方案的候选仅为 B、DX、stock，不把多个外部后端混合；除相对 stock 的 speedup 外，再报告 `T_B / T_补位`，直接说明补位是否优于 B。

1. **算子级**：按 `Stotaway/results/算子级结果表.md` 和原预测器的多模型清单逐项使用相同物理 MNK、TP8、dtype、通信方向与 16 连发口径，列出 stock、四个外部方法和 DX 的时间/相对 stock speedup；区分 AG、RS、up、gate_up、down 及实际支持范围。对已有 A800 DX/stock 测量逐格核对设备、数据类型、形状、执行路径、通信、16 连发及计时协议：匹配的直接复用，不因为增加 baseline 重跑；未匹配或为同批对照所必需的缺口才补测。不把四卡、双卡数据直接并入八卡表。
2. **Qwen3.6-27B 训练**：Megatron 上分别对四个 baseline 进行实际 E2E 接入、命中验证和同配置性能测量；对每个已接入的 B 测其 B+预测器+DX/stock 补位方案，同时报告 stock、B、DX/已有计划与补位方案，包含 step time、tokens/s、speedup、实际调用点和运行配置。沿用或对齐既有 MBS、序列长度、层数和数据口径；可复用已有对应载具及结果。用户允许的截层模型载具是端到端实验，应明确记载层数/数据/权重等配置以便对齐，不以层数定义是否为 E2E。
3. **Llama3-70B 推理**：在 vLLM 分别接入四个 baseline，按相同权重、tokenizer、输入输出长度、batch 和 TP8 比较 stock、B、DX/已有计划、B+预测器+DX/stock 补位；记录 TTFT、吞吐、总时延、speedup 和路径命中。沿用既有有效 TP8 配置/结果，仅补对应新方案和必要同批基线。
4. **预测器与最终表**：在算子和 E2E 分别记录方案选择、未知形状选择正确率（目标 80% 以上）、被选方法、相对 stock 和 B 的实际 speedup、布局转换和规划开销；将四个 baseline、DX 和四种各自补位方案汇成可追溯结果表，列出原始时延及 speedup，沿用 BW1000 原表术语与结构，单机 8 卡即可。该表同时保留逐点不支持或失败的信息及运行日志，不把未跑的格子写成 1.00×。

四个 baseline 的训练和推理 E2E 都属于本次目标，先做源码/接口适配和真实执行；若某项在实际适配后确实无法运行，应保留失败日志和明确缺口，不能假称已经测过，也不以算子结果代替 E2E。此前已存在的样本、测试数据和模型不会删除。所有实验与结果清单完成并记录后，本次任务结束。

## 当前决策：双卡最小闭环已验证，可以切八卡

2026-11-13 增量：`stowaway_nvidia/replacement_plan.py` 已实现固定 Async-TP + DX + stock 的 TP2 BF16 前向算子载具。人工覆盖计划在同一运行中每 rank 命中 stock 12 次、Async-TP 8 次、DX 4 次（含批量检查）；18 次独立调用和 6 次批量调用均与参考一致，8 次未知/不匹配调用回退 stock；两 rank 计划 SHA 一致，计划或调用顺序不一致被集体拒绝，保留结果未被后续调用覆盖。另以此前 Async-TP 三臂已测数据自动生成 `measured_existing` JSON，该计划两处均选 DX，真实调用成功；它是已知形状实测选择，不是未知形状预测。证据与代价见 `双卡后端族预测实验进度_20261112.md`。该闭环满足下述切卡触发条件，现可切八卡。

执行器目前每次 `run` 通过 Gloo 交换元数据，测得每调用有明显控制面成本；`run_batch` 将 16 个预先准备的独立调用合并一次校验，但不能表达真实模型层间依赖，也不能把其结果当模型收益。现在已完成的是 **TP2 算子载具闭环**，不是 vLLM/Megatron 集成、未知形状预测或 TP8 闭环；后者属于切八卡后的 M2–M4。

当前机器是两卡 A800。四个外部方法已有双卡算子数据，继续扩大双卡形状矩阵不是切换八卡的前置条件。八卡已有 DX 原型与历史数据；现在可按以下已实现的最小闭环转入 TP8 预检和正式矩阵。

当前最小闭环选 **Async-TP 的 AG/RS、DX 和 stock**：三者现有双卡算子实验均已运行且可对照标准逻辑分片，优先避开 FlashOverlap 的 packed tile 衔接问题。这个选择只决定先接哪一个，不改变四个外部后端的正式比较范围。执行器应使用已有实测数据和现有预测器接口；示例计划必须明确区分人工指定、实测选择和模型预测，不能把人工选择称为预测结果。先让不同调用点真实走不同候选，并测试每个候选与 serial 参考一致；再验证保存/加载 JSON、跨 rank 一致、未知或不兼容回退、重复输入及输出生命周期，并记录执行耗时和命中路径。无需先完成四个后端的全部模型接线、未知形状 80% 或模型 E2E 才允许切八卡。

**切八卡触发条件（已达到）**：上述至少一个外部后端的三候选计划可以在同一双卡载具中按调用点执行并通过检查，测试日志和 JSON 可审阅。切八卡后先做 TP8 拓扑和四后端最小正确性检查，再按下面的 M2–M4 执行；保留现有 TP2、TP8 和四卡历史数据。八卡可用不等于三候选系统已完成，M2–M4 仍须实测。

## 系统目标

固定一种外部重叠后端 B，对工作负载中每个调用点选择 B、DX 或 stock；计划必须满足形状、前后向、dtype、张量语义、分片与布局约束。DX 仅补位值得替换的位置，不同时引入其他外部后端。stock 指算子内的 NCCL AllGather→GEMM 或 GEMM→NCCL ReduceScatter。计划将每个点的选择与精确环境/实现签名绑定，并由各 rank 一致执行。

## 原理与算法草案

每个位置 i、候选 a 的总成本估计可表示为 `T_i(a) = 算子耗时 + 布局适配耗时 + 额外同步/资源开销`；允许候选仅为语义和能力验证通过的 B、DX、stock。端到端计划使用 `T_step ≈ T_common + Σ_i count_i*T_i(a_i) + interaction(plan)`；仅有测量支持时才使用交互项，未知项不冒充零。实际选择应同时考虑一次性探测/编译/规划成本和调用次数：如果选择方案节约总时间不足以覆盖开销，保留既有路径。该公式是设计目标而非当前已完成的三候选模型或性能保证。

已实现部分：执行签名分计算、通信 API、内存、传输、同步、GPU/拓扑、TP/dtype/软件、具体路径和计时协议；按 route 拟合相对收益（如 `log(T_stock/T_overlap)`）、局部物理族修正、JSON 模型和部分计划缓存；已有同一方法或 DX/stock 的执行示例、跨 rank 校验、保守回退、整步组合原型。实验结果存在环境依赖，未证明所有路由未知形状均超过 80%。详见 `预测器原版与NVIDIA版对照_20261113.md` 和 `双卡后端族预测实验进度_20261112.md`。

新增 Async-TP TP2 算子载具的三候选实际执行与已测值选择；尚未实现跨后端未知形状预测器、B 与 DX 真实模型逐点调用/切换及净收益、交错行 DX 的 TP8 与模型反向。现有 `unified_step.py` 是固定方法的二选一，不要用其证明跨后端预测。

## 重叠和重排序

TP2 DX 以标准 GEMM 及 CUDA 异步 peer copy 等机制为基础，NVSHMEM 对称缓冲提供 peer 映射，ticket/ACK 保证读写顺序，Triton 做归约；RS 先算发往 peer 的块、重叠后续本地计算，AG 把发送、接收和分块 GEMM 交叠。TP8 `DirectExchange8` 是多 peer 原型，已有 rank 相对发送顺序和批量 ACK 选项，性能因形状而异。与论文一、FlashOverlap、FiCCO 等先例须具体区分，不能将常规分块重叠或重排当首创。

TP2 新增可选交错逻辑行直出：按目标 rank 的交错行切片进行分块 GEMM，让输出为 `rank::world` 的逻辑行，避免事后跨 rank 行重排。FlashOverlap 原生 tile 是另一布局；在 RS+归一化合成链中分别使用其 `ReorderRMSNorm` 与 DX 逻辑行 + Triton RMSNorm，两者结果对同一参考通过，M1024/2048 三组 DX 比值为 1.1544×/1.3192×。这是 TP2 前向原型、不同归一化实现与已见形状，不是 TP8、packed tile 直接兼容或模型 E2E 结果。可探索的系统贡献是布局语义约束和衔接代价纳入逐点补位，而非宣称重排本身首创。

## 四个完成里程碑

1. **M1 补位能运行**：至少先将一个已验证兼容的外部后端与 DX、stock 组成可执行 TP2 方案；产生可审阅 JSON，所有 rank 校验同计划，在不同调用点实际执行不同候选；验证同一输出语义、重复输入和切换，不改变另一后端原始实现。再按需扩展 Async-TP、Triton-distributed、FlashOverlap、Syncopate 适配器；不声称四个已完成。
2. **M2 TP8 可用**：确认机器拓扑及实际路径；复用已有 DX8 对照，在四个方法支持的各一个 AG/RS 路径做 TP8 正确性与 16 连发预检；处理新布局/反向能力，不支持记录 N/A。至少一个外部方法完成 B+DX+stock TP8 调用点切换。
3. **M3 预测器**：按完整 route 单独标定，冻结后对没参与调参的物理形状族采真实标签；相对 B 和 stock 分别统计选择正确率、延迟/损失、额外探测及摊销成本。目标准确率 ≥80% 是实测目标，不作保证；反复运行仍低于目标就继续优化或如实报告。固定方法内不混其他外部方法。
4. **M4 E2E**：Llama3-70B 推理、Qwen3.6-27B 训练分别完成同配置 stock、DX/原已有方案与可执行补位计划对照；有条件再对各外部方法分别做 B、B+DX+stock。记录模型形态、权重、精度、关键路径命中和计算通信布局；当前仓库中没有证据证明四个外部方法都已有现成目标模型 E2E 接口。

## 八卡最小矩阵与扩展

1. 初始预检：8 卡型号、拓扑、空闲、软件、模型与数据；每个方法只测其支持的 AG/RS 正确性，核验实际调用而非仅导入。已有结果和编译缓存不删除。
2. 算子：Llama3-70B 推理与 Qwen3.6-27B 训练实际投影清单（QKV、o_proj、fc1、fc2，区分 full/gated attention），提取真实 TP8 局部 M/N/K、dtype、前向/反向；优先代表小、中、大 M 与用户 BW 原表同配置，再按资源覆盖全部实际清单；每个支持格 stock、B、DX、选择方案，16 连发、多次独立进程交错，报原始时间、比值、正确性、布局和失败。FlashOverlap 只测其实际支持的操作，Syncopate 区分实际生成路径与论文图手写路径；不将不支持填成 1。
3. 预测器：算子训练/测试按物理维度族分开；评估已有后端全用、DX 全用、stock 全用、预测计划和事后最优；报告准确率、实际速度/负收益次数、计划成本、布局开销、回本次数；测消融 route 特征、重排、交互/净成本。避免对同一目标先调参再称盲测。
4. Llama3-70B/vLLM：同权重、tokenizer、TP8、batch、上下文和生成长度，复用原表已有结果；选具有代表性的 prefill 和 decode 配置，测 TTFT、吞吐、总时延、显存；精度和输出质量不以 token 完全相同作为唯一准入。对有实接接口的后端增补 B 及 B+计划。
5. Qwen3.6-27B/Megatron：同 64 层文本配置、seq/MBS/重算/优化器与数据，先复用 seq4096 MBS1/2/4/8 已有结果，补缺失的新方案和需要的配对而非重跑全部；前向和反向分开核对命中、step time、吞吐、显存、loss/梯度。明确随机权重训练载具与 HF 实权重训练是否真正等价，不能把存在共享 HF 文件当作已完成权重映射。

当 M1–M4 都有可复现结果和上述能力边界记录时，称本任务范围内的系统实现与实验完成；外部方法无法在目标框架接入时，明确列出哪些 E2E 不支持，不能把算子结果充当 E2E。是否达到论文强结论由真实结果决定。八卡租期无法仅凭双卡数据准确承诺：预检与代表算子为短窗口，四种后端接入及两个模型端到端需根据实际故障、编译与吞吐调整；不承诺特定时长或必然大于 1×。
