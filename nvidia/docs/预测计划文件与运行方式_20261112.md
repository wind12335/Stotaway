# 预测计划文件与运行方式

## 当前可实际运行的 JSON 路径

TP2 DX 的诊断入口已有完整文件流程：使用已采集的前向+反向样本生成 JSON，Megatron 加载 JSON 后按实际 `(site,M,K,N)` 决定该位置用 DX 或 stock。一个现成的示例文件为 `/root/data/stowaway-nvidia/results/qwen36_tp2_training_export_v2_20261112.json`，是当前 A800、TP2、BF16、PyTorch/Triton/连接设置下的诊断计划，不适用于其他环境或未列形状。

```bash
cd /root/Stotaway/nvidia
python planner/build_tp2_lookup.py \
  /root/data/stowaway-nvidia/results/tp2_qwen36_fwbw_conn1_m*_s551_20261112.json \
  --objective training \
  --output /root/data/stowaway-nvidia/results/my_qwen36_training_plan.json

STOWAWAY_DX=1 \
STOWAWAY_TP2_LOOKUP=/root/data/stowaway-nvidia/results/my_qwen36_training_plan.json \
PYTHONPATH="$PWD/third_party/qwen36_fla${PYTHONPATH:+:$PYTHONPATH}" \
STOWAWAY_QWEN36=1 STOWAWAY_QWEN36_LOCAL_SPEC=1 \
STOWAWAY_LAYERS=4 STOWAWAY_HIDDEN=5120 STOWAWAY_FFN=17408 STOWAWAY_HEADS=24 \
STOWAWAY_SEQ=2048 STOWAWAY_ITERS=5 STOWAWAY_GBS=2 STOWAWAY_COLUMN_MAX_N=20000 \
NVSHMEM_SYMMETRIC_SIZE=2G TEST_TIMEOUT=450 \
OUT=/root/data/stowaway-nvidia/results/raw/my_qwen36_training_plan.log \
bash experiments/run_megatron_smoke.sh
```

`my_qwen36_training_plan.json` 若已存在会拒绝覆盖；数据来源不可用时不能复现该命令。训练入口是四层、随机初始化、mock 数据的诊断载具。这个 lookup 是基于同形状标定的保守选择，不是对全模型或未知形状作出的保证。当前历史样本 metadata 没有记录 warmup 字段，输出中的 `warmup: null` 表示来源缺失，不能把它误写为已记录；后续采样会记录数值。

日志中 `STOWAWAY_TP2_LOOKUP` 打印两 rank 的 SHA256 和配置类型，`STOWAWAY_TP2_CHOICE` 打印调用点及选择。两 rank 各自完成读取/校验后交换摘要和错误，如果不一致会整体报错；不匹配的 GPU/软件/连接配置拒绝加载，未列出的具体形状默认 stock。`STOWAWAY_TP2_INTERPOLATE=1` 可选启用受限插值，默认关闭。

2026-11-12 对示例 JSON 进行了双卡四层训练 smoke：两 rank 摘要一致，M2048 的 `proj` 与 GDN 输出对应 `fc2` 命中 DX，其他点按计划回退；五步训练完成。独立前后向算子批次 18/24、几何平均 1.023×、0 慢点；其中有同形状复测，不是未知形状泛化或完整训练 E2E。日志 `/root/data/stowaway-nvidia/results/raw/qwen36_tp2_json_export_v2_20261112.log`，结果 `qwen36_tp2_training_export_v2_holdout_20261112.json`。

## 统一整步模型导出

`planner/original_a800/export_tp2_step_plan.py` 提供 Python 接口，把 `unified_step.choose_step` 的结果、原始调用清单、相同整步标定和模型来源转换成现有 TP2 训练 JSON。它校验调用清单和整步标定摘要、DX 实际路径、前后向、运行时签名、适配器形状以及同名映射冲突；`write_json_new` 不覆盖已有文件。CPU 测试覆盖导出、现有 `Lookup` 加载、未知形状回退及参数不匹配。

已增加针对四层 Qwen 诊断的实际数据构建器 `planner.original_a800.build_qwen_step_diagnostic`：在 M1024/3072/4096 的前后向算子样本上拟合、将 M2048 排除，再以 M2048 的整步交错块标定 proj/fc2 的逐点残差和组合交互，导出 `/root/data/stowaway-nvidia/results/qwen36_tp2_unified_step_diagnostic_v2_20261112.json`。它选择 fc2，GDN 与 MLP 两种实际形状分别进入模型；两个 rank 均加载同一 SHA 并在五步训练中按预期选择，日志 `qwen36_tp2_unified_step_v2_smoke_20261112.log`。算子模型对目标 M 留出，但整步残差直接使用目标 M 的实测值，因此不是未见工作负载预测；fc2 形状次数 6/8 基于四层结构与总计数推断，未做逐形状计数验证。该示例不能说明自动适配所有模型、后端或证明整步收益。

随后启用 `STOWAWAY_LOG_SHAPE_COUNTS=1` 独立验证了上述载具的累计调用次数：每 rank 五步分别为 proj 10、GDN fc2 30、MLP fc2 40，与每步 2/6/8 一致。日志 `qwen36_tp2_unified_v2_shape_counts_20261112.log`；该计数只适用于当前执行设置。

基于这些计数生成的 v3 审计文件 `qwen36_tp2_unified_step_diagnostic_v3_20261112.json` 增加每个候选的算子预测与整步残差分解；它和实际运行过的 v2 的设备要求、工作负载要求及所有调用点选择完全一致，并通过 CPU 载入校验，v3 文件本身没有再单独启动双卡训练。`conservative_delta_ms` 的名称来自接口，当前示例输入的不确定度为 0，不代表保守置信界或稳定收益。

冻结后独立三组交错 stock/计划对照，按同编号步骤配对的 speedup 几何平均 **1.0016×**（每组分别 0.9973×、1.0044×、1.0031×）；按整次中位数相除为 1.0157×，会受长短步分布影响。详见 `qwen36_tp2_unified_v2_holdout_20261112.json`。这是有限次数的随机 mock 训练载具，不是完整 27B 模型性能结论。

另有一条独立的实验性整步实测 mask 路径：`planner.original_a800.export_paircal_mask` 将三个配对交错块中已测组合的选择和已知 M2048 调用形状导出为同一训练 JSON，文件 `/root/data/stowaway-nvidia/results/qwen36_tp2_paircal_measured_mask_20261112.json`，选择 fc2（覆盖 GDN 和 MLP），其他调用点 stock。双卡五步实际运行，两 rank 文件 SHA256 均为 `4c1f731e7468ece8822a8edb1f5cdfb1df0d2598631c31f3eca957a96a24c0e0`，两个 rank 均命中两个 fc2 形状的 DX 且 proj 选择 stock，正常结束；日志 `/root/data/stowaway-nvidia/results/raw/qwen36_tp2_paircal_mask_smoke_20261112.log`。这是四层随机 mock 训练载具、只含 M2048 的调用点清单，不是完整 Qwen 模型或未知形状计划。该导出路径由整步测量选择已测组合，不是 `unified_step` 的算子回归及交互建模；性能需单独对照。

**使用限制：**旧 JSON 只检查 GPU、软件、TP、dtype、连接设置和形状。新导出计划支持 `workload_requirements`，会检查层数、维度、序列、并行和重计算等列出的 Megatron 参数，并由所有 rank 汇报加载错误；将序列改为 1024 的双卡实测中，两 rank 均拒绝该 2048 计划。校验只覆盖记录的字段，不是完整工作负载指纹，也不验证输入数据、时钟和所有配置；未包含要求的历史 JSON 保持原行为。在线模型决策和动态能力校验仍未实现。

## 实时方式

可做“进程启动/新形状首次出现时用已保存模型推理，再把选择缓存”或“启动前离线输出 JSON”；不要求每次调用都重新测量或拟合。当前代码支持模型 JSON 载入和 Python 内选择，但**尚未接入多 rank 的在线模型决策**。要实现这一方式，必须由 rank0 统一决策并让各 rank 达成一致、处理动态 shape、图捕获和模型版本；动态选择的开销需要计入实验。也可以进一步做运行期探测，但要单独计成本和探测对上下文性能的影响，现阶段未实现。

新增 `CachedRouteSelector` 作为进程内按完整 route、形状、能力证据、测量特征与门槛缓存的原型；注册表对模型做快照，新注册模型会使旧缓存条目失效。它尚未对接 Megatron/vLLM 的在线决策；下述多 rank 接口已做独立测试，尚未测端到端运行期开销。

新增 `distributed_inference.prepare_collectively`：各 rank 在执行前提交相同 query 批次，先交换请求摘要与错误，再由组内首 rank 预测并广播结果；shape、route、能力证据或特征不一致会整体报错。双 A800 的 NCCL 和 CPU Gloo 两 rank 测试均覆盖相同请求、能力不一致、主 rank 无模型、单 rank 非法输入，均正常结束。NCCL 10 次热态调用中位约 0.90–0.98 ms/批，首次调用约 0.4–0.7 秒（含分布式惰性初始化和进程时序）；这是小型控制面 microbenchmark，不代表 Megatron 真实端到端开销。调用必须由全部组成员按同顺序预先进行，不应放在每个算子热路径或 CUDA graph capture 中；rank 失联时仍依赖进程组超时。Megatron 已接入预先列出的静态形状批次，vLLM 和执行中自动发现新形状仍未接入。

已在现有 Megatron 诊断入口增加可选 `STOWAWAY_TP2_ONLINE_BUNDLE`：初始化后两 rank 校验同一 bundle 的设备和工作负载，集体推理预先列出的 6 个已核实形状并保存本地决策，训练调用中只查字典，未列入的形状回退 stock。M2048 的 bundle `/root/data/stowaway-nvidia/results/qwen36_tp2_online_operator_bundle_20261113.json` 用 M1024/3072/4096 前后向算子数据拟合，M2048 的既有已检查报告仅用于确认形状支持，不用于拟合目标形状耗时；目标报告此前已参与研发，不是盲测。两个 rank 真实运行五步，预测 proj 和两个 fc2 为 DX，其他形状为 stock，正常完成；日志 `qwen36_tp2_online_operator_smoke_20261113.log`。这是算子级预测汇总，未考虑整步交互，也不支持运行时自动发现新形状或 vLLM；启动时的列举清单和能力证据仍需外部提供。

将上述 2048 bundle 放到序列 1024 的工作负载进行了双 rank 负例，两个 rank 均报告 workload mismatch 并退出，日志 `qwen36_tp2_online_wrong_workload_20261113.log`。这只验证字段不匹配的拒绝行为，未知形状的 stock 回退由 CPU 测试覆盖。

另增加 `dynamic_query.py`：调用方在已同步的安全点提供真实 route、shape 和能力证据，调用 `prepare_collectively` 后可将广播结果插入缓存，并拒绝已有同键冲突。双卡 NCCL 微型测试已验证新形状的集体决策和缓存写入；这仍不是 Megatron 自动动态形状支持，实际执行过程中需要上层保证所有 rank 在同一顺序到达安全点。无能力证据或不具备同步条件时应继续使用既有 stock 回退，不可在 kernel 热路径直接触发 collective。

当前接口在本 rank 的 CUDA graph capture 中直接拒绝，不会尝试发起 collective；各 rank 仍须由调用方保证一致处于安全点，否则另一 rank 可能等待至进程组超时。未知 shape/未知能力默认 stock，已注册配置或测量证据发生变化需要重新生成模型文件。

针对已知误判点可以用 `planner.original_a800.add_tp2_calibration_override` 给 bundle 添加同形状测量覆盖项；两个 rank 会在覆盖后再次核对完整 decisions。M2048 MLP fc2 示例输出 `qwen36_tp2_online_operator_calibrated_20261113.json` 并实际跑过；与未覆盖计划的四组交错配对为 1.0004×，极小且不稳定。覆盖测量应与 bundle 的实际执行环境、batch 和测量条件核对；历史 bundle 的 warmup 未记录，不能把它和已记录 warmup=3 宣称完全一致，当前示例保留这项未知信息，后续生成器会显式标记。该方法不能自动决定要标定哪个形状。

`RoutePolicy` 可保存为 JSON 并由统一注册表和缓存加载。已把 18 条 FlashOverlap TP2 数据冻结为 `/root/data/stowaway-nvidia/results/flashoverlap_tp2_route_policy_20261113.json`，双卡载入后两个 rank 对示例形状均返回 stock。该试验只验证模型文件与预测通信，并未调用 FlashOverlap 算子或证明模型性能；先前五点独立重复的通用策略仍为 2/5、0.9824×。

随后新增 `bench/flashoverlap_online_policy.py`，将该策略在 FlashOverlap RS 双卡算子载具中实际执行，分别覆盖选 stock 和选 overlap。该载具仍是算子级示例，并非对 FlashOverlap 上游端到端的通用注入；一次决策后只初始化选中的 native communicator。两个点的单独对照中，选 stock 的点错过 1.0645×，选 overlap 的点获得 1.0858×（独立进程采样，有漂移）；完整数据及限制见双卡实验进度。
