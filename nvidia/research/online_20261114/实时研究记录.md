# 在线查新和 AG 粒度：实时记录（2026-11-14）

此次通过本机代理访问 OpenAlex、Crossref 和 arXiv，检索 compute-communication overlap、predictor、adaptive chunking、tensor-parallel scheduling、strategy selection；检索并非穷尽。arXiv API 返回 Rate exceeded，但论文摘要页面和 PDF 可访问。PDF/TXT 为阅读副本，结论以论文具体内容为准。

## 新发现：非常接近的预测系统

- [OverlapAdvisor，arXiv:2611.11857](https://arxiv.org/abs/2611.11857)，2026-11-09 提交，已阅读摘要、§2–4。针对 MoE 专家并行 A2A，提出统一性能预测器、配置感知选择和 serving launcher，在 vLLM/SGLang 中对多个 MoE 策略进行启动时选择，并据计算/通信粒度诊断修改 DeepEP-v1 和 FlashMoE。它与我们的“重叠有不同优势区间 → 建模 → 选择 → 框架运行 → 粒度指导”叙事高度重合；不能主张该大框架首创。我们的当前任务为 dense TP 的 AG/RS，每次固定一个 B，以 B/DX/stock 做投影点选择；模型是基于 MNK 的 route 独立拟合与模型族残差。任务/候选/模型形式有差异，尚不能证明系统新颖性或完全不撞车。
- [CoCoPeLia，ISPASS 2021](https://doi.org/10.1109/ISPASS51385.2021.00015)，[开放全文](https://eprints.gla.ac.uk/320559/1/320559.pdf)：针对 CPU↔GPU BLAS offload 的三路并发，建立重叠预测、自动 tile size 选择和运行时调度；明确讨论切分大小与计算效率和流水线的权衡。不是 TP8 GPU↔GPU AG，但“预测驱动的计算通信分块粒度”并非首创。
- [Domino，arXiv:2409.15241](https://arxiv.org/abs/2409.15241)：§3.1 训练前 benchmark/grid search 确定 tensor partition granularity，目标是兼顾计算效率和 TP 通信重叠；涉及 Megatron 训练及 row/column tensor slicing。直接反驳“首次按计算效率自动选择张量分块”。
- [KOSMOS，arXiv:2611.07477](https://arxiv.org/abs/2611.07477)，2026-11-05 提交：MI350 TP+SP/EP persistent kernel，用依赖就绪队列在通信与计算角色间自动切换；AG 本地 tiles 优先并与远端 tile 交错，明确比较固定 split、逐次预测 split。其机制和平台与 A800 DX 不同，但“依就绪情况协调 AG 通信与计算”也有直接先例。

## 可发展的问题，而非已证明创新

AG 将通信粒度（每 peer 发送与 ready/ACK）与 GEMM 粒度（每次合并多少个 peer 块）分离：通信仍可逐 peer 推送、逐 peer 发布 ready；计算可合并多个完整 peer 行块，避免将缓冲过早重用，并根据就绪状态决定处理顺序。必须保证目标 rank 的行输出位置及输入的生命周期；不能在一块被复制/读取完之前向发送方 ACK，也不能混淆 CUDA stream 上同步关系。按 shape 从小候选 `{1,2,4,8}` 选择 GEMM 合并大小可以作为性能优化，但 coarse-grain chunk 选择及双粒度模型已有 OverlapAdvisor/Domino/CoCoPeLia 先例；潜在增量只能是针对 TP AG 的依赖、内存布局、rank 间交互和真实集成机制，并需进一步与先例比对及验证。

现有八卡 DX 中，发送每个 peer 块并发布信号，消费者逐 peer 等待、copy 到临时缓冲后 ACK，再调用分块 GEMM；M=8192 的 local block 为 M/8。此前单卡 99 点比较 8 块 GEMM/完整 GEMM 中位 1.173×，AG 的部分代表形状 1.2–1.4×。单卡没有跨 GPU 数据、网络和等待，不能用它计算 AG 净收益或正确性。

## 进一步相关工作

- [Lagom，arXiv:2602.20656](https://arxiv.org/abs/2602.20656)，2026-02-24：分布式 LLM 训练中以统一成本模型与优先级搜索联合调优通信参数，考虑计算通信争用。它与整步资源/通信调参方面相关；并不支持声称“首次模型化争用或统一成本模型”。
- [Mercury，SOSP 2025，DOI:10.1145/3731569.3764798](https://doi.org/10.1145/3731569.3764798)：OpenAlex 的摘要指出其基于 CommIR 对远程 GPU 内存进行编译时整体调度、自动探索数据放置与设备间通信，并可重现已有人工策略；目前只核对元数据与摘要，未读全文，不能断言与 DX 分组或我们的选路问题互斥。
- [Centauri，ASPLOS 2024，DOI:10.1145/3620666.3651379](https://doi.org/10.1145/3620666.3651379)：Crossref/OpenAlex 给出完整题目，摘要明确研究大模型训练中的通信分区和计算通信重叠；OpenAlex 没有公开全文链接。仍需全文核查具体算法，不作“完全不同”结论。

## 单卡就绪数据原型结果

`experiments/single_gpu_ag_grouped_ready.py` 用 rank=3 shift 顺序模拟本地已就绪 8 rank slots，比较逐 peer copy+GEMM、逐 peer 直接读、连续 peer 最多 2/4/8 组的直接读；对 12 个 Llama3-70B/Qwen3-32B AG 形状均通过本地输出对照。相对逐 peer copy+GEMM，ag_gu 中位分别 1.035×/1.082×/1.141×/1.145×，ag_up 中位 1.087×/1.158×/1.226×/1.214×。真实跨 rank 通信、等待、ACK 与重叠尚未测；direct 路径不能在本地 GEMM 未读取完时发 ACK。详见 `results/a800/单卡AG相邻分组原型_20261114.md`。
