## 3. 算子实验：形状、计时、数据契约

### 3.1 形状与优先顺序

从 `planner/data/cells.json` 和 `planner/shapes.py` 读取现成矩阵，保留仓库原有 `(model, op, M, N, K)`：11 模型，`M=8192,16384,32768`，`ag_gu`（gate-up）、`ag_up`（up）及 `rs`（down），共 99 点。M 是完整投影的全局行数，AG 每 rank 输入行数为 M/TP；N/K 的含义以原载具和调用语义为准。不要把 M=32768 误记成每 rank 的 32768。

论文当前代表图先测 7 个模型各 3 个操作、M=32768，共 **21 个形状**：`llama3-8b`, `qwen3-32b`, `llama4-mav-d`, `mistral3-d`, `llama3-70b`, `qwen25-72b`, `mistral-l-2407`。然后补余下形状达到 99 点。算子矩阵的 FFN 形状不等于已覆盖四个实际 E2E 投影；QKV/o_proj 的真实形状以目标模型 manifest 为准，按 E2E 接入需要补齐，不冒称已有 99 点包含全部位置。

先查旧异常 `llama4-mav-d/ag_gu/M32768` 和 `qwen3-8b/rs/M32768` 的串行 GEMM 与完整路径，两点原始值保留，补采结果另存并记录 GPU 状态、代码、分母；不要只选更漂亮的一次。

### 3.2 每点采样和共同基准

- 对每个形状、平台、dtype、TP 和操作，在同一批执行同一串行路径（AG→GEMM 或 GEMM→RS）与 DEO、已接入的 B。尽量同一次进程或同一交错批次，记录运行顺序、设备状态、实现和计时边界。串行保持相同实现、输出语义和数据类型；图上的 1.00× 对应同形状同 dtype 的同批串行。
- 每组连续发出 16 次并除以 16；8 个重复组，按现有载具规则跨 8 rank 取慢 rank，再保存每组的 **serial 和各候选原始耗时**、中位耗时、独立进程/批次标识。不同臂顺序尽量交错以减少漂移，保留原数据。
- 柱值沿用 `median(serial_8) / median(candidate_8)`，不要把它写成“八个 speedup 的均值”。范围为 `median(serial_8) / candidate_j` 的八个值的最小/最大；这是观测范围，不是统计置信区间，也没有包含串行端的不确定性。若明确证明每组严格配对，可以另存配对比值，不能把非配对测量冒充配对。
- 不同 dtype 或不同串行参考不能悄悄合并成严格同一基准；若某 B 仅支持 FP16，则同批重新测 FP16 serial 与 DEO，并独立标记。FlashOverlap 的计时范围须注明是否包含重排/布局恢复，优先统一为完整投影路径；区分不可用与 0。
- 输出建议每点 JSON：`platform, device, topology, software_versions, commit, model, site/op, M,N,K,tp,dtype, batch=16, repeats=8, run_order, serial_samples_ms, candidate_samples_ms, median_ms, correctness, timing_scope, source_files`；再派生 CSV：`serial_reference_median_ms,candidate_median_ms,speedup,lower_observed,upper_observed`。保存每 rank 原值或其可追溯聚合，并记录精度、通信库、配置和原始错误。

已有运行入口：`README.md` 的 `source env/env.sh`、`python3 tools/check_env.py`、`bash bench/smoke.sh`、`bash e2e/paper.sh ops`，以及 `bench/ag_gemm.py`、`bench/gemm_rs.py`。现有脚本的输出位置、初始化与耗时先实际检查；不要仅运行旧脚本就声称已保存逐组样本。为本次补测增加非覆盖输出目录与机器可读样本记录。

## 4. 新版预测器与真实派发实现

1. **数据导入**：构造 BW Route：设备、拓扑、TP、dtype、操作、计算后端、通信后端和计时协议；串行和候选取 BW 实测。每个路径、AG/RS 分别训练，避免使用 A800 的参数和配置覆盖 BW。
2. **训练与测试**：用 `RouteLocalResidual` 所在实现的形状收益预测（`log(serial/candidate)`）以及按模型族留出的残差修正。在按模型族留出测试时，所有基础拟合、残差库均只用训练族，得到 held-out 逐点预测。固定超参数后用训练集拟合部署模型；保存版本、训练样本列表、参数、数据 hash。历史二选一数据可先用于打通，补齐实际 B 的 BW 测量后训练对应 B。
3. **生成方案**：从真实目标框架配置或实际观测获得四处投影的 `site,op,M,N,K`，并绑定设备、TP、dtype、后端、默认路径。每点在可执行的 serial、DEO、B 中比较预测收益，输出 JSON、收益估计、选择和来源；不要把 NVIDIA 固定示例形状当作 Hygon 真实调用。区分 `qkv`、`proj`、`fc1`、`fc2` 与算子基准 `ag_gu/ag_up/rs`。
4. **加载与派发**：扩展现有 Hygon 接入，检查所有 TP rank 读取相同方案；以一致顺序初始化所需 DUSHMEM、通信组、缓冲区及后端上下文。模型命中投影时按方案调用对应完整路径，符合输入输出布局、通信语义及训练反向；未匹配调用按明确默认路径执行并计数。输出每路径实际命中和回退原因，确认方案选择确实被运行。
5. **外部后端**：逐个核查源码、许可证、依赖与 DTK 兼容性，只编译当前要用的部分；按其需求实现参数、通信、布局/重排与输出恢复。记录每项能否运行、支持操作/dtype、性能计时范围及原因。不假设 Async-TP、Triton-distributed、FlashOverlap、Syncopate 均已在 BW 上可用。

## 5. 端到端：训练与推理

### 5.1 Megatron 训练

目标是 **Qwen3.6-27B 训练**。旧 `SW_MODEL=27b` 载具参数 `hidden=5120, ffn=17408, heads=40, kv=8, NL=32, seq=4096`，请实际核对它与目标模型配置、层数及运行方式的关系，记录真实模型或随机初始化、数据来源、TP/SP、MBS、重计算与优化器。此前的 27B 载具结果保留，不能直接替代新版 OPRS/Qwen3.6 实测。

固定一次 B（如已可用）做同批臂：

| 臂 | 行为 | 目的 |
|---|---|---|
| Serial | 相同模型、串行 GEMM+RCCL，原模型/框架参考另记 | 1.00× 参考 |
| Null | 相同 hook/堆配置但不替换 | 分离接入本身开销，复用原仓库口径 |
| Always DEO | 四处可用位置使用 DEO | 测固定策略 |
| Always B | 四处 B 可支持的模块使用 B，其余串行；标明覆盖 | 测单后端 |
| OPRS | 新模型生成 JSON，按位置在 serial/B/DEO 中派发 | 测规划加补位 |

无可运行 B 时先做 serial / null / DEO / OPRS 二选一，别阻塞其他工作；待 B 接入后加对应两臂。每臂用独立进程并按 ABAB 或合理交错重复，保存每步耗时、loss、显存和路径命中；报告同批 `serial/arm`、`B/OPRS` 及 `DEO/OPRS`，切勿用跨日基线冒充同批。训练需检查前向、反向/梯度和 loss 的有限性与合理误差，记录条件与结果。

### 5.2 vLLM 推理

目标 **Llama3-70B 真实权重推理**，参考旧单机配置 TP8、BF16、完整 80 层、prefill M=16384。分开记录原始 vLLM AllReduce 路径与 SP-RCCL 串行参考；分别报告各臂相对两者的 speedup。臂为原 vLLM、SP-RCCL、全 DEO、新版 OPRS，以及实际可用的每个 B 与 B+OPRS。记录 TTFT、吞吐、实际预填 token、模块路径命中、初始化和输出数值；使用既有自然文本检查与必要的 logprob 比对，原始结果保留。历史 `plan` 是旧预测器，不与新版 JSON 混写。

## 6. 新版预测器实验和消融

同一批数据进行模型族留出，逐点记录预测收益、choice、每候选真实时间、真实最佳、正确与否、相对最佳损失、是否慢于串行；按 B 和 AG/RS 分开展示数量、准确率、几何平均 speedup。比较：

1. 串行、固定 DEO、固定 B；
2. 仅形状基础岭回归，和加入模型族留出残差近邻修正的版本；
3. 预测生成的方案，及以同批实测最佳候选构造的事后最优参考；
4. 少数代表点运行由方案实际派发的路径，记录耗时和命中，与离线预测对应；
5. 对训练和推理分别记录生成方案、加载与执行的开销，必要时按真实模块执行频次解释算子收益与 E2E 的关系。

不要把按族留出评估、已有历史回放、样本内训练表现与独立目标模型实测混为同一准确率；明确所有分母和样本数，完整保存失败点。
