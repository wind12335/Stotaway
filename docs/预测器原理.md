# 预测器（创新点 2）原理 —— 最终版（11-01）

代码：`planner/`
- `planner.py`：统一规划脚本（输入模型形状和 MBS，输出 4 个调用点各用哪种方法）
- `costmodel.py`：第一级（算子级代价模型）
- `step_planner_v3.py`：第二级（整步控制面项）的拟合与留一检验
- `validate.py`：第一级的留一模型检验

术语见 `docs/术语表.md`。中间过程（被否定的 v2 第二级、各批实验）见文末附录和 `results/findings.md` F47–F51。

## 0. 预测器要解决什么

一层 Transformer 有 4 个调用点（GEMM 和通信挨着的位置）：

| 调用点 | 是什么 | 通信 |
|---|---|---|
| QKV | 注意力输入投影 | 先 AG 再 GEMM |
| o_proj | 注意力输出投影 | 先 GEMM 再 RS |
| fc1（gate_up） | MLP 第一层 | 先 AG 再 GEMM |
| fc2（down） | MLP 第二层 | 先 GEMM 再 RS |

每个调用点有三种做法：原版（厂商 GEMM + RCCL 串行）、重叠方法（创新点 1）、拆批（把 batch 拆开，一份的通信和下一份的 GEMM 同时跑）。

没有一种做法处处最快，而且最优组合**随形状变**。同一个 70B 模型就是例子：

| 70B 的 MBS | 实测最优 |
|---|---|
| 8 | fbc（四处全用重叠方法） |
| 4 | fbag（RS 两处用重叠方法，AG 两处用原版） |
| 2 | base（四处原版） |

预测器在**训练开始前**给每个调用点选做法，选定后整个训练不变。

为什么不在训练中现场试：在本平台上，一个做法的通信上下文（对称堆 + 拷贝流）一旦建起来，即使释放，也会改变之后引擎操作的速度（F44），现场试本身会把结果测歪。所以只能预测。

**规划时的输入**（都不建通信上下文）：
1. 模型形状（hidden、ffn、heads、kv 组数、层数）和 MBS；
2. 单卡测一次 4 个 GEMM 的时间（每个形状几秒，`planner.py` 自动做）；
3. 原版配置短跑 ≤3 次迭代，读出整步时间（用来算每层周期 GPU 时间）。

## 1. 第一级：算子级代价模型（每个调用点单独估时间）

**平台标定**（一次性，用两张算子级表格拟合）：
- C(B)：RCCL 传 B 字节的时间，RS 和 AG 各一条直线；
- Cx(B)：重叠方法自己的纯通信时间。RS 侧直接测到；AG 侧测不到，设 Cx = k·B，k 和下面的系数一起拟合。

**三种做法的时间公式**：
- 原版：T = G + C(B) + h0
- 重叠方法：T = a1·G + a2·Cx + a3·max(G, Cx) + h1
  - max(G, Cx) 是理想重叠：计算和通信哪个长取哪个；
  - a1·G、a2·Cx 补"重叠不完美"：GEMM 被通信抢带宽变慢，第一块 GEMM 和最后一块通信藏不住；
  - h1 是一次融合调用的固定开销。
- 拆批：预测相对原版的加速比 r，log r = w0 + w1·log(G/C) + w2·log B + w3·log(G/N)，N = 2 或 4 份。
  - 计算和通信越接近一样长，拆批越有效；每份 GEMM 太小时效率下降，拆了反而亏。

系数按相对误差最小二乘拟合，RS、AG 的 up、AG 的 gate_up 各一套。

**安全门**：每种做法取"预测过于乐观的幅度"的 80% 分位 q，预测时间乘 exp(q) 作悲观估计，悲观估计仍要比原版快 2% 以上才选。

**检验**（留一模型，11 个模型、97 个调用点，连发计时）：

| 指标 | 值 |
|---|---|
| 选中方案比原版慢的格子 | 0 |
| 几何均值加速：预测器 | 1.139× |
| 几何均值加速：总用重叠方法 | 1.101× |
| 几何均值加速：静态 M 阈值 | 1.120× |
| 几何均值加速：事后最优 | 1.167× |
| 拿到事后最优收益的比例 | 83% |

## 2. 第二级：整步控制面项（第一级看不见的平台代价）

### 2.1 现象
第一级会把 27B 和 70B 的 AG 两处都判成用重叠方法（算子级确实更快）。整步实测：

| 点 | fbc（四处全用重叠方法）相对 fbag（RS 两处用重叠方法，AG 两处用原版） |
|---|---|
| 27B MBS8 | +3.05%（输） |
| 27B MBS4 | +3.26%（输） |
| 70B MBS8 | −1.68%（赢，4 次均值） |
| 70B MBS4 | +2.21%（输） |
| 70B MBS2 | +4.77%（输） |

### 2.2 机理（11-01 定位，F50）
- 本平台上，对**另一个进程的显存**做引擎拷贝时，HIP 会把 host（CPU 侧）拉回到 GPU 进度附近（每次被拉回约 GPU 落后量的 25%）。这和拷贝次数、大小、分叉写法、拷贝 API 都无关；同进程跨卡拷贝和本卡拷贝不会。
- 重叠方法的每次推送都属于这一类（每张卡一个进程，推进对端的对称堆）。
- 融合 AG **先推后算**：每次调用都把 host 的提前量几乎清零，之后 GPU 要等 host 重新发命令，形成空泡。RS **先算后推**，被自己的 GEMM 盖住一部分，所以 RS 两处照样赢。
- 三种改法（槽位多份、等确认挪门流、分叉改写值）都位级正确，但车内无效。结论：这是平台代价，预测器必须把它算进去。

### 2.3 模型（AG 两处）
按层周期计算（层周期 = 一个 micro-batch 走完一层的前向 + 重算 + 反向）。D = 每层周期 GPU 时间 = 整步 / (层数 × micro-batch 数)。

  每次融合 AG 调用的 GPU 空等：e = k × D（当 D < D\*），否则 e = 0
  开重叠方法的 AG 调用点集合 S 的整步变化 = Σ_S ΔD_site + 2 × e × |S|

- ΔD_site = 2 ×（重叠方法 − 原版），来自第一级；乘 2 是因为每个 AG 调用点在前向和重算里各调用一次。
- k = 0.0096，D\* = 205 ms。D\* 被数据夹在 137 到 273 ms 之间，取中点。
- 含义：GPU 时间短时，host 被拉回后要重新追上去，空等随 GPU 时间增长；GPU 时间够长时，host 来得及在这层做完前重新领先，空等被盖住。
- 选择：在 {都不开, 只 QKV, 只 fc1, 都开} 里取预测整步最快的；只有预测至少快 1% 才开（防 E2E 噪声误判）。

由实测反推的 e：

| 点 | D | e |
|---|---|---|
| 27B MBS8 | 137 ms | 1.69 ms |
| 27B MBS4 | 74 ms | 0.65 ms |
| 70B MBS4 | 134 ms | 0.96 ms |
| 70B MBS2 | 77 ms | 0.73 ms |
| 70B MBS8 | 273 ms | ≈ 0 |

### 2.4 模型（RS 两处）
RS 两处作为一组开关，对应 fbag 的 RS 部分：前向融合 GEMM+RS、反向融合 AG+dgrad、独立 RS。实测相对原版：

| 点 | fbag 相对原版 |
|---|---|
| 27B MBS8 | −6.37% |
| 70B MBS8 | −7.44% |
| 70B MBS4 | −5.80% |
| 70B MBS2 | +3.1%（F30，10-29 测） |

规则：D < 111 ms 时 RS 组回退原版。截止点只由 1 个输点确定，被夹在 80 到 143 ms 之间（见 §4 局限）。

### 2.5 拆批
第一级会给出拆批选择，但拆批还没接进训练（E2 待办），所以最终选择暂时只在重叠方法和原版之间做；脚本会同时标出"算子级最优是拆批"的调用点。

5/5 选对。这些点也是第二级的拟合数据，属于样本内。

### 3.2 第二级的留一检验（`step_planner_v3.md`）
每次拿掉一个点拟合，再预测这个点：

| 定律 | 选择正确 | 平均绝对误差 |
|---|---|---|
| 只用第一级（无控制面项） | 4/5 | 3.05 个百分点 |
| e ∝ D（无截止） | 3/5 | 2.93 |
| **e ∝ D，D ≥ D\* 时为 0（采用）** | **4/5（80%）** | **1.44** |
| e = 常数 − 一部分 D | 4/5 | 2.35 |

唯一选错的是 70B MBS8：它是唯一高于截止点的点，拿掉它就没有数据能估截止点。达到用户定的 80–90% 门槛。

### 3.3 例子：70B MBS8（`python3 planner.py --model 70b --mbs 8 --step-ms 18892`）

| 调用点 | 第一级 原版 / 重叠 (ms) | 最终选择 | 理由 |
|---|---|---|---|
| QKV | 6.18 / 4.98 | 重叠方法 | D = 278 ms ≥ D\*，无空等；QKV + fc1 都开整步预测快 1.46% |
| o_proj | 7.99 / 5.58 | 重叠方法 | RS 组，D ≥ 111 ms |
| fc1 | 17.02 / 16.19 | 重叠方法 | 同 QKV |
| fc2 | 11.06 / 6.57 | 重叠方法 | RS 组 |

可部署配置：fbc。同一模型 MBS4 时，D = 142 ms < D\*，QKV 和 fc1 的空等各 1.36 ms 抵掉了收益，选 fbag。

## 4. 局限（如实）

1. **截止点只被夹住**：AG 的 D\* 在 137–273 ms 之间，RS 组的截止点在 80–143 ms 之间。论文按区间写，不再补点（用户门槛 80–90% 已达到）。
2. **RS 组截止点只有 1 个输点，而且是 10-29 测的**。11-01 的 fbag 绝对速度比 10-29 同配置快 5–7%（70B MBS4 8583 vs 9095、MBS2 4922 vs 5300），原因未查。如果今天的 fbag 在 70B MBS2 上也能赢原版，RS 组截止点就要下移。要确认，需要同批复测 70B MBS2 原版和 fbag 各两遍，8 卡约 10 分钟，约 1.3 卡时。
3. **第二级的点只覆盖两个模型（27B、70B）**；"e 只取决于每层 GPU 时间"在两个模型上成立（27B MBS8 与 70B MBS4 的 D 相近，e 也相近），更多模型未测。
4. **拆批未接进训练**，最终选择暂时是二选一。
5. D 由原版短跑得到；第二级拟合用的是 fbag 口径的 D，脚本按 fbag / 原版 = 0.94 换算（实测 0.926–0.955）。
