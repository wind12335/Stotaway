# 3.2 基于算法特性的分布式通信优化方法

大模型分布式训练的性能在很大程度上受制于集群内部的集合通信开销。为使通信延迟不再拖累训练的整体效率，本研究以基于算法特性的分布式通信优化为主线展开体系化研究：从训练与推理过程中的典型通信模式入手，剖析各通信原语同计算任务之间的依赖关系，面向国产 GPU 平台探索通信—计算协同优化机制，力求在保持架构兼容性的同时取得可观的运行性能收益。

研究按三个层次递进。第一层次对高频使用的通信原语作功能分类与耗时剖析，考察各训练阶段中 All-Reduce、All-Gather、Reduce-Scatter 等操作于何处被调用、何时触发以及占用多长的通信时间，并在多卡环境验证 Tensor Fusion[3]、Local SGD[4] 等典型通信优化策略，界定各自的适用场景与性能边界。第二层次对 FLUX[5]、FlashOverlap[6] 两项前沿计算—通信重叠方法开展复现与评估，考察其在国产 GPU 适配、调度粒度与性能稳定性方面的长处与不足，并据此选定 Triton-distributed[7] 作为自研重叠算法的基础。第三层次在前述工作之上形成本阶段的方法体系：以不经集合通信库调度的直连数据通路承载分块传输，以融合算子把通信摊入计算间隙，并以两级预测器按模型形状自动选择各通信点的实现路径，在单机 8 卡与双机 16 卡的训练、推理两类场景完成端到端验证。

面向 All-Gather 场景的形状感知超块重叠方法 SASO-AGGEMM 与面向 Reduce-Scatter 场景的前沿对齐双阶段生产者调度方法 FA-DPPS，相较传统串行执行方式与 Triton-distributed 原生实现均已取得明显提升。本阶段进一步把两类方法推向系统化，使通信优化从单一算子的点状改进，扩展为覆盖两类原语、可逐调用点配置、由预测器自动决策的完整技术链条，为国产 GPU 上大模型的训练与推理提供了可行路径。

## 3.2.1 通信原语筛选

为甄别各类通信原语对训练性能的影响程度、给后续优化路线提供依据，在单机双卡环境部署了通信行为监测实验：借助训练性能分析工具 hipprof 统计 Qwen3 模型微调全程的通信调用情况，并分别在常规微调、Tensor Fusion 与 Local SGD 三种设置下考察通信开销的变化。

①常规微调（对照组）。统计结果见表12：即使微调场景的模型规模不大，All-Reduce 依然构成最主要的通信负担，调用次数与累计耗时占比均为各类原语之最（800 次调用、耗时占 69.2%），表明梯度同步始终是制约训练效率的主要通信因素。表内其余原语中，广播操作虽仅 98 次调用、耗时占比却达 30.3%，且单次平均耗时（约 7.3 ms）明显高于集合规约，提示权重与输入的分发环节同样值得留意。后续优化应以规约类操作为主要对象，可行的手段包括压低通信触发频次、扩大单次通信的粒度，以及以计算—通信重叠隐藏同步等待。

②使用 Tensor Fusion。该方法先把多个小规模梯度张量汇聚成较大的桶（bucket），再以桶为单位发起集合通信，与逐张量各自执行 All-Reduce 的做法相比，减少了小张量通信的频繁启动开销并压降调用次数。由表13可见，All-Reduce 调用次数由 800 降至 240、耗时占比降至 35.4%，小粒度梯度同步引发的通信开销得到有效缓解；同时广播操作的耗时占比升至 63.8%、跃居首位，说明该策略下通信开销的重心由规约转向分发，两类操作需协同考虑。

综合三组实验：三种策略分别从触发频次、聚合粒度与同步间隔入手压减通信开销，各有明确的适用条件，但均未改变通信与计算交替占用硬件的串行执行方式；而大模型训练中计算与通信具备天然的流水并行潜力，把二者交叠执行才是更根本的出路。本研究据此将计算—通信重叠确立为此后的主要优化方向。

## 3.2.2 计算-通信重叠技术

计算—通信重叠的核心思想，是在模型计算语义保持不变的前提下，对矩阵计算、张量同步与数据传输实施并行调度，尽量把通信等待时间藏进计算过程。为考察此类技术在国产 GPU 环境下是否适用、还有多少优化空间，选取融合式方法 FLUX 与信号触发式方法 FlashOverlap 两项代表工作，于单机双卡环境完成复现与性能分析。两类方法分别代表"深度融合"与"内核外轻量协同"两种技术取向，对比复现有助于划定自研方法的设计空间。

FLUX 属融合式路线的代表性工作。该方法先把原本各自执行的矩阵计算与集合通信超分解为更细粒度的数据分块，再借内核融合把彼此衔接的计算分块与通信分块编入同一个 GPU 内核：每个分块映射到独立的线程块，不同分块交错执行，从而在不损伤内核效率的前提下隐藏通信，并能与 GPU 架构及互联拓扑较好适配。其优化目标有二：把 All-Gather 及其后续 GEMM 合入单一内核，以及把 GEMM 及其后续 Reduce-Scatter 合入单一内核。复现实验基于其公开源码完成，结果留存作为后续研究的对照。

实验共设六组：单纯执行 GEMM 的对照组，用于标定矩阵计算本身的执行基线；稠密 MLP 的两类组合，即 All-Gather 接 GEMM 与 GEMM 接 Reduce-Scatter，对应前馈网络中的两组典型通信—计算衔接；以及 MoE MLP 中专家计算与跨设备通信的三类组合（对应 T2E1、T1E2 两种专家分组配置）。结果见表15—表18。仅执行单卡 GEMM 时，PyTorch 原生实现（3.087 ms）反而快于 FLUX（3.952 ms），可见其长处不在孤立的单次矩阵计算，而在于复杂分布式组合中把通信等待藏进计算：All-Gather 接 GEMM 的组合中，总耗时自 16.67 ms 降至 13.60 ms，其中通信项由 5.38 ms 压缩至 0.18 ms，近乎被计算完全掩盖，未开启通信优化的对照为 16.38 ms、与原生实现相当；MoE 组合的总耗时亦自 26.74 ms 降至 22.28 ms。GEMM 接 Reduce-Scatter 的组合却呈相反走向：总耗时自 16.17 ms 升至 18.05 ms，通信项虽由 5.88 ms 缩至 1.62 ms，融合内核的 GEMM 计算项却膨胀至 16.43 ms，通信节省被计算膨胀吞没。实验同时暴露出融合式路线的共性局限：其一，通信逻辑被深度织入 GEMM 及分组 GEMM 内核，实现与维护复杂度陡增；其二，此类设计往往要求手写或大改通信原语，NCCL 等成熟通信库的既有优化难以直接继承，跨通信模式、跨硬件平台与跨模型结构的泛化能力因此受限，数值一致性亦需另行处理。

针对融合式方法的上述不足，进一步考察基于信号机制的重叠方案 FlashOverlap。与深度融合路线不同，FlashOverlap 走信号触发的轻量路线：在 GEMM 内核里设置轻量信号点，计算每完成一个数据片即主动置位信号，内核之外的通信流程监听到信号后，随即启动该数据块的传送。它既不要求对 GEMM 做粗粒度拆分，也无需把通信原语重写进计算内核，原有高效计算路径得以原样保留，同时获得 tile 级（数据片级）的计算—通信重叠能力（图17）。验证实验仍在单机双卡环境开展，重点检验该方法同 All-Reduce、Reduce-Scatter 等常用原语组合后，在不同矩阵规模下的加速表现（表19）。小规模矩阵（2048³）下收益有限，All-Reduce 组加速比甚至略低于 1（0.9945），个别场景出现轻微波动；矩阵规模上去之后，计算与通信各自持续更久、重叠空间随之展开，加速效果逐渐显现：自 2048³ 增至 16384³，All-Reduce 组加速比由 0.9945 攀升至 1.2915，Reduce-Scatter 组由 1.0222 增至最高的 1.5177。究其原因，小矩阵的计算与通信都转瞬即逝，能藏进计算里的通信窗口本就不多，信号触发与数据重排的固定开销便显得沉重。精度方面，优化前后的数值偏差处于可忽略水平，稳定性表现良好；且该方法不改动 GEMM 的划分与调度方式，对已经充分优化的计算内核而言，这种内核外协同的设计更易移植到不同平台。

## 3.2.3 形状感知超块重叠技术

### 3.2.3.1 直连数据通路与融合算子

重叠方法的系统化围绕数据通路与算子两个层面展开。

数据通路层面，分块传输不再经由集合通信库调度，改由各卡自行驱动：参与通信的进程各自在显存中预留一块跨进程对称内存堆（各进程于相同地址预留、可互相直接访问的显存区域），本卡计算完成的分块经直接内存访问写入目标卡的接收缓冲；发送次序按置换顺序错开，避免多卡同时压占同一链路；数据依赖由设备侧旗标配合流上的等待原语维持，全程不引入全局同步屏障。GEMM 内核本身不承载任何通信逻辑，保持厂商算子库的原生实现，从根源上规避了融合式方法侵入内核、难以复用成熟算子库的缺陷。

算子层面，通信与计算的耦合由融合算子承担。以行并行 GEMM 与 Reduce-Scatter 的融合为例：GEMM 输出按接收方切分、逐块计算，每完成一块立即推送至目标卡，通信被摊入相邻计算块的执行间隙，等价于把一次集中执行的集合通信化整为零嵌入计算流水；对端汇总为一次完成的单遍归约求和。反向传播中 All-Gather 与梯度计算的融合同理实现；前向 All-Gather 与列并行 GEMM 的融合（先推送后计算）作为候选路径一并保留。一个 Transformer 层内此类通信点共四处——注意力 QKV 投影、注意力输出投影、前馈第一层与第二层投影，每处均可在融合路径与原版路径之间独立选择。

由此产生配置问题：四处调用点的最优组合并非恒定，而是随模型形状与每卡处理的词元数（词元即 token，模型处理的基本文本单位；该数值等于序列长度与微批规模之积，微批规模指梯度累积之前单卡一次处理的样本条数）变化。实验中，27B 负载的最优选择为后两处融合、前两处保持原版；70B 负载在每卡 32768 词元时四处融合最优，每卡 8192 词元时则应整体退回原版。最优配置随形状漂移的现象，直接催生了 3.2.3.4 的两级配置预测器。

### 3.2.3.2 算子级验证

算子级实验在海光 BW1000 八卡环境（张量并行度 8）开展，覆盖 Qwen3-8B 至 Llama3.1-405B 的 11 个主流稠密 Transformer 模型，每模型考察每卡词元数 8192、16384、32768 三档；对照双方为厂商 GEMM 算子库加 RCCL 集合通信的串行执行，与训练过程中实际调用的同一融合算子。测量遵循三条纪律：其一，每格以独立进程运行——同一进程内先后建立、拆除通信上下文会拖慢后续测量一至两成，必须隔离；其二，采用连续提交计时（连发 16 次算子不等待完成，总时间除以 16，重复 8 次取中位数，并取八卡中最慢一卡的数值），以贴近训练中通信与计算相互掩护的真实节奏；其三，每格结果均与 fp32 参考逐格比对校验。

汇总结果见表21。GEMM 与 Reduce-Scatter 融合全面占优：32 格中 30 格更快，整体几何均值达 1.302×，且收益随词元数递增——8192 档 1.112×、16384 档 1.343×、32768 档 1.496×，最高 1.845×（DeepSeek-V3 稠密层）。GEMM 与 All-Gather 融合呈现明显的规模效应：小词元档整体不占优（8192 档几何均值 0.878×），32768 档 21 格中 20 格更快、几何均值 1.127×、最高 1.425×（Qwen2.5-72B）。精度方面，融合算子对 fp32 参考的相对误差介于 0.62%—1.02%，全部小于原版 RCCL 沿环路逐跳以 bf16 累加的 1.45%—2.74%：单遍 fp32 归约求和的数值表现优于逐跳累加，融合路径未引入精度损失。

### 3.2.3.3 端到端训练验证

端到端实验基于 Megatron 训练框架：序列长度 4096，张量并行 8 卡并启用序列并行（将序列维度切分至张量并行组各卡），完整重计算，bf16 精度。被测负载两个：27B（隐藏维 5120、前馈维 17408、32 层）与 70B（隐藏维 8192、前馈维 28672、64 头 8 KV 组、受显存所限截取 8 层）。整步时间取每臂 14—18 次迭代自第 3 次起的中位数；每臂独立进程，并在同一批次内交错执行两遍，以抵消机器状态漂移。

为剥离运行环境自身的干扰，实验引入空载对照：其软件环境、对称内存堆与包装层与优化配置完全一致，但不接管任何算子。以空载对照为基准的加速比即纯重叠收益，作为下文主口径；空载对照相对原版的偏差介于 −1.3% 至 +1.0%，源于对称堆带来的内存布局变化，与重叠机制无关。

以 70B 为对象扫描微批规模，每卡词元数自 4096 增至 32768，整步加速比依次为 1.013×、0.969×、1.062×、1.080×：收益随词元数单调增长，其中 8192 档不升反降（该档仅独立 Reduce-Scatter 被接管）。融合收益存在明确的规模下限，"处处开启"并不可取，路径选择必须结合形状判断。27B 上的逐级消融进一步分解收益来源：仅将反向传播中旁侧无 GEMM 可融合的独立 Reduce-Scatter 替换为直连通路的纯通信实现，整步加速 1.016×；叠加前向融合后增至 1.060×；再叠加反向融合达 1.068×——收益主体来自融合算子，纯通路替换的贡献有限。正确性方面，16 卡全部臂次迭代完整执行、无数值异常，各配置的损失曲线与原版处于同一区间，与算子级逐格校验结果互相印证。

### 3.2.3.4 通信优化配置预测器

鉴于最优配置随形状变化、逐项试错代价高昂，本研究建立两级预测器，在训练启动前自动完成各通信点的路径决策。

第一级为算子级代价模型。以已测形状的耗时数据为样本，离线拟合各通信点在融合与原版两种方案下的耗时（按相对误差加权、按矩阵规模分项），并内置保守安全门：仅当某方案的悲观估计（预测值乘以训练集上该方案乐观偏差的 80% 分位数）仍比原版快 2% 以上时方予选用，否则回退原版。以 11 个模型、97 个通信调用点作留一模型检验（每次保留一个模型的全部调用点不参与拟合、专用于检验）：预测器捕获事后最优收益的 83%（连续提交计时口径，1.139× 对事后最优 1.167×；单次计时口径为 87%，1.142× 对 1.163×），97 格中没有一格慢于原版，融合方案耗时预测误差为 9.2%／6.7%（两种口径）。若撤除安全门，收益升至 1.149×，但会出现 4 格慢于原版、最差慢 8.1%——"不比原版慢"的保证正是安全门的价值所在。

第二级为整步控制面修正项。仅凭算子级数据无法刻画主机端（发起算子调用的 CPU 侧）的发射代价，其机理经专门实验定位：本平台对属于其他进程的显存执行引擎拷贝时，主机端进度会被拉回至 GPU 进度附近；融合 All-Gather 采用先推送后计算的次序，每次调用先行发出多次推送，主机端阻塞随之转化为 GPU 空等，而每层 GPU 时间足够长（约 205 ms 以上）时空等又被本层计算掩盖。据此建立修正模型：每次融合 All-Gather 调用引入的 GPU 空等，按每层周期 GPU 时间的 0.96% 计（该时间低于约 205 ms 时成立，超过则为 0）；Reduce-Scatter 组在每层周期 GPU 时间低于约 111 ms 时整体回退原版。检验情况见表23：留一检验（8 卡五个整步实测点）4/5 选对、平均绝对误差 1.44 个百分点；统一规划脚本在 8 卡全部实测点上 5/5 选对；在 16 卡上作为纯样本外检验 2/2 选对，两负载所选配置分别较未被选择的配置快 3.46% 与 2.77%（两遍同号），且 27B 与 70B 的最优配置恰好相反，印证了按形状逐点决策的必要性。

### 3.2.3.5 推理场景验证
