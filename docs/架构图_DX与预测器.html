1　一张图看全系统

系统分三块：先收集几样输入；预测器在训练开始前用纯 CPU 算出每个调用点用哪种做法；运行时只按这个方案接管对应的调用点。方案一旦选定，整个训练过程中不变。

一句话：DX 把 TP 通信（AG、RS）切成和 GEMM 一样的 R 块，算完一块就由拷贝引擎按置换序直接推给它的归属卡，靠 4 字节票据对齐，不设全员栅栏；预测器在训练前判断每个调用点开不开它，因为在本平台上"算子级更快"不等于"整步更快"。

2　DX 怎么做 GEMM + RS（o_proj、fc2 的前向）

行并行的线性层：每张卡用自己那份 K 算出完整的 M 行部分和，再做 ReduceScatter（RS），让第 d 块行最终落在卡 d 上、并对 R 张卡求和。原版是"整块 GEMM 算完 → 再调 RCCL RS"，两件事串行。DX 把 M 行切成 R 块，每块都有一张"归属卡"：

  • 分块计算：要送给别人的块先算，自己的块最后算。这样第一块推出去时，后面的 GEMM 还在算，通信就藏在计算后面。
  • 直推：用拷贝引擎（DMA，专门搬数据的硬件，不占计算单元）把整块直接写进归属卡的对称堆。不经过 RCCL，也不经过任何中转卡；对称堆由 dushmem 分配，它只负责分配和换算对端地址。
  • 票据：每块数据后面紧跟一个 4 字节票据，写在同一条拷贝流上，所以票据到了就说明数据已经到了。归属卡用 hipStreamWaitValue32 只等自己堆里那几个格子，不设全员栅栏：慢的那张卡只拖慢它自己那一块。
  • 求和与 ack：R 份到齐后，一次 fp32 累加。求和结束后发 ack（一个原子交换小核写进发送方的格子），发送方下一次要复用这个槽位之前会先等它。

3　为什么按"置换序"推

第 j 步，卡 r 推给卡 (r + j) mod R。下表的每一列里，每个目的地恰好出现一次。也就是说，同一时刻每张卡只收一份、只发一份，没有"多张卡同时往一张卡里挤"（incast）。

发送卡 \ 步第 1 步第 2 步第 3 步
卡 0→ 1→ 2→ 3
卡 1→ 2→ 3→ 0
卡 2→ 3→ 0→ 1
卡 3→ 0→ 1→ 2
  • 实测（8 卡，F-perm）：8 张卡同时按置换序直推，每张卡约 141 GB/s，推给哪个对端都一样快。所以不需要环（ring）那种 7 跳"边加边转发"，一跳就到归属卡，求和只在终点做一次。
  • 对比：FiCCO 是 1/8 粒度扇出（同时发给所有人），多条流并行。我们是一次只发给一个目的地，按步轮换。这是两者的主要取舍：我们换来了无 incast、单流、票据顺序天然有序，代价是每步只有一条流在用。

4　DX 怎么做 AG + GEMM（QKV、fc1 的前向）

列并行的线性层，序列并行下：每张卡只持有 M/R 行输入，GEMM 之前要先 AllGather（AG）出全部 M 行。DX 反过来：先把自己那份按置换序推给所有人；自己的块先算；别人的块到一块算一块。

  • 收到的块先从对称堆搬到普通显存，再交给 GEMM，因为 GEMM 的操作数不能放在堆上。搬运放在旁路流上，搬完就发 ack。
  • 反向的 AG + dgrad（o_proj、fc2 的反向）是同一个机制：收集的是输出梯度，每到一块就算这块的 dgrad。wgrad 等全部到齐后算一次。
  • 算子级上 AG+GEMM 在大 M 时赢（M32768 几何均值 1.13×），小 M 时多数输（M8192 0.88×）。进了训练整步还有一个算子测试看不到的代价，见 §6。

6　为什么算子级赢、整步却可能输：控制面

同样是融合 AG，算子级更快，可在 27B 训练整步里四处全开（fbc）反而比只开 RS 组（fbag）慢 3.05%。原因不在数据传输上，而在 host（CPU 发命令的一侧）上：

  • F50（11-01 定位）：本平台上，拷贝引擎往另一个进程的显存（对称堆或 IPC）写数据时，host 会被拉回到 GPU 进度附近。这与拷贝次数、大小、分叉写法、用哪个 API 都无关。我们是每卡一个进程，推送全是这一类。
  • AG 吃亏、RS 不吃亏：AG 是先推后算，推送一开始就把 host 的提前量清零，GPU 随后要等 host 重新发命令。RS 是先算后推，被它自己的 GEMM 盖住了一部分。
  • 槽位多份、换等待流、改分叉写法三种改法都试过，位级正确但整步无效，所以这是平台代价，不是 bug。
  • 一层的 GPU 时间 D 越长，host 越来得及重新领先，空等就被盖住。所以同一个 70B 模型：MBS8（D = 273 ms）开 AG 赚，MBS4、MBS2 开 AG 亏。这就是需要预测器的原因：最优组合随形状变。

7　预测器两级怎么算

第一级：算子级代价模型（每个调用点单独估时间）

做法预测时间各项含义
原版T = G + C(B) + h0G：单卡 GEMM 实测；C(B)：RCCL 传 B 字节的时间（直线拟合）；h0：固定开销
重叠（DX）T = a1·G + a2·Cx + a3·max(G, Cx) + h1max(G, Cx) 是理想重叠；a1·G、a2·Cx 补"藏不完"（GEMM 被抢带宽变慢、首块和末块藏不住）；h1：一次融合调用的固定开销

系数按 RS、AG-up、AG-gate_up 三类分别拟合，用的是 11 个公开模型 × 3 种 M 的实测数据。安全门：先算"预测过于乐观的幅度"的 80% 分位 q，把预测时间乘以 eq 得到悲观估计，悲观估计仍比原版快 2% 才选重叠。留一模型检验（每次拿掉一个模型拟合，再预测这个模型）：97 个调用点里 0 个选得比原版慢，拿到事后最优收益的 83%。

第二级：整步控制面项（把 §6 的空等算进去）

  • D = 每层周期 GPU 时间 = 原版整步时间 × 0.94 ÷（层数 × micro-batch 数）。层周期 = 一个 micro-batch 走完一层的前向 + 重算 + 反向。
  • 每次融合 AG 调用的 GPU 空等：e = 0.0096 × D（D < 205 ms），否则 0。
  • 开 AG 的调用点集合 S（从 {不开, 只 QKV, 只 fc1, 都开} 里选）的整步变化 = ΣS（第一级预测的算子级收益 × 2）+ 2 × e × |S|。乘 2 是因为每个 AG 调用点在前向和重算里各被调用一次。选预测最快的那个，而且要预测快 ≥1% 才开。
  • RS 组作为一组开关：第一级选重叠，且 D ≥ 111 ms 才开。只有 70B MBS2 这一个输点，截止点只被夹在 80–143 ms 之间。

已知局限：推理（vLLM）上第一级偏保守。vLLM 只有前向，所以只用第一级。M16384 时，第一级只给 o_proj、fc2 开重叠，QKV、fc1 判成原版：算子级表里 70B 的 AG+GEMM 只有 1.01× / 0.98×，加上 2% 安全门后就被否决了。实测四处全开比它的选择再快：单机 8–10%，双机约 3%。安全门起了作用（从没比原版慢），但漏掉了一部分收益。下一步做归因：只开 QKV、只开 fc1 两臂，然后修正第一级。修正后如果原理有变化，本图会另出一版。

8　MoE：整层去掉 host 同步

MoE 层的通信是 all-to-all（a2a）。Megatron 原版每层要把 token 计数读回 host 两次（.tolist()），每次都让 CPU 停下来等 GPU。我们把这两次读全部去掉：

  • 结果：算子级整层（前向 + 反向）1.17–1.57×；8 卡 EP8 端到端 1.116×；单卡只换专家 GEMM 1.188×。
  • 定位：免同步 a2a 已有先例（DeepEP 低延迟、MORI-EP、HybridEP），论文里写成框架下的一个实例，不单列贡献。贡献点在"控制面决定整步收益"这个论点：只换数据面，MoE 整步慢 13–18%；把控制面（host 同步）也去掉，整步快 11.5%。

10　组会讲稿（约 5 分钟）

  1. 问题（30 秒）：TP + 序列并行训练里，每层有 4 处通信（2 个 AG、2 个 RS）和 GEMM 串行。原版是厂商 GEMM + RCCL，一个算完另一个才开始。
  2. DX（1.5 分钟，看 §2–§4 两张时间线）：把 GEMM 切成 R 块，算完一块就用拷贝引擎直推给它的归属卡，不占计算单元；按置换序推，同一时刻每张卡只收一份，实测每卡 141 GB/s；4 字节票据跟着数据走，只等自己的格子，不设全员栅栏。同一机制用在 4 个调用点的前向和反向。算子级 GEMM+RS 1.30×。
  3. 为什么需要预测器（1 分钟，看 §6）：融合 AG 算子级更快，但在本平台上，往别的进程显存推数据会把 host 拉回 GPU 附近，GPU 随后空等。所以同一个 70B，MBS8 开 AG 赚，MBS4、MBS2 开 AG 亏，最优配置随形状变。
  4. 预测器（1 分钟，看 §7 的图）：第一级按形状和单卡 GEMM 时间预测每个调用点的算子时间，带安全门；第二级把空等 e 写成 D 的函数，D 越长空等越被盖住。训练前算一次，纯 CPU，几秒。8 卡 5/5，16 卡样本外 2/2。
  5. 结果（1 分钟）：Megatron 整步 1.06–1.08×（8 卡、16 卡一致）；vLLM 完整 70B prefill 1.14–1.17×，16 卡 1.19–1.22×，输出逐 token 一致；MoE 去掉 host 同步后端到端 1.116×。
  6. 局限与下一步（30 秒）：推理上第一级偏保守（漏掉 3–10%），下一步做归因并修正；第二级数据点少；只测了一个平台。
