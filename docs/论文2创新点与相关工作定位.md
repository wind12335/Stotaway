# 论文 2（Stowaway）：和论文 1 的重叠有什么不同、创新点在哪、用已有工作说明控制面创新

11-09 写。代码级逐项对照在 `docs/论文1与论文2差异分析.md`，相关工作逐篇精读在 `tri-dist-hygon/docs/OPUS_related_work_4papers_20261030.md`。本文是这两份的合并结论，供写论文用。

术语：
- **数据面**：数据怎么搬，包括拷贝引擎推送、RCCL 内核、SM 直写。
- **控制面**：谁在什么时候发出命令、等什么信号，包括 host 入队、流上等待、host 同步。
- **调用点**：一层里 GEMM 和通信挨着的四个位置，即 QKV、o_proj、fc1、fc2。
- **整步**：一次完整训练迭代（前向 + 重算 + 反向 + 优化器）。

---

## 1. 一句话

论文 1 回答"重叠怎么做得更好"。论文 2 回答"重叠在真实训练整步里什么时候才赚、在哪个调用点开"。论文 2 的答案是：整步收益由控制面决定。我们给出控制面的实测定律，并据此做了一个训练前离线决定每个调用点开不开重叠的两级预测器。

## 2. 重叠机制：和论文 1 代码的不同

结论先说：**协议骨架继承自论文 1，不能列为论文 2 的贡献。**骨架包括：推送到对端暂存槽、同一条流上紧跟票据、单调序号、消费后释放槽位、`(rank + j) % R` 发送循环。逐行对照见差异分析 §2.1。

真正的不同点，按能否在论文里讲成设计取舍排序：

| # | 维度 | 论文 1 | 论文 2（DX） | 怎么写 |
|---|---|---|---|---|
| a | GEMM 与通信的耦合 | RS / AG 用 Triton GEMM，内核里原子计数发信号、按 tile 等待 | 厂商 GEMM 按块调用 `torch.matmul`，块间用流事件交接，内核里没有任何信号 | 设计约束：厂商 GEMM 一行不改，训练反向的 dgrad/wgrad 也能直接用。BW1000 上论文 1 形态只有 vendor+RCCL 的 0.32–0.42×，差距全在 Triton GEMM（S18）。注意论文 1 的 AR 路径已是 cuBLAS 分块，所以只能说"RS/AG 上不同" |
| b | 生产顺序 | 所有 rank 对齐算同一目的地 + 前沿优先 | 每个 rank 旋转，第 j 步算给 (r+j) 的块，自己的块最后算 | 按平台选调度：A100 NV12 每对卡独立链路，BW1000 实测置换序约 141 GB/s/rank、扇出和 incast 慢 |
| c | AG 方向与栅栏 | 拉 + 每次调用两次全员栅栏 | 推 + 每次调用无栅栏 | 训练里每层前向、重算、反向都要反复调用，栅栏代价放大 |
| d | 覆盖面 | 只有推理前向（`@torch.inference_mode`） | 训练前向 + 重算 + 反向（AG+dgrad、独立梯度 RS）+ vLLM prefill | 场景扩展，也是第 3 节控制面问题能暴露出来的前提 |
| e | 粒度 / 窗口 | 面板粒度可配，L 个窗口槽 | 固定 M/R 一块，不开窗口 | 论文 1 设计空间的一个角点，不写成新东西 |
| f | 同步原语位置 | 等远端 free 标志；票据用 WriteValue32 | 只等本卡格子，对端用小核远程写；票据用 4 B 引擎拷贝 | DCU 平台逼出来的工程改动，放实现细节 |

论文里的写法：设计一节用一段话说明"沿用 [AnchorOverlap] 的票据交接协议，在厂商 GEMM 不改、训练整步的约束下重新实例化"，再列 a、b、c 三个取舍。双盲期间论文 1 按第三方文献引用。

## 3. 论文 2 的创新点

### 创新点 1（主）：控制面定律，即算子级赢不等于整步赢

| 现象 | 数据 | 出处 |
|---|---|---|
| 融合 AG 孤立快，整步反而慢 | 融合 AG 孤立 1.29×；27B 四处全开（fbc）比只开 RS（fbag）慢 3.05% | F17、F49 |
| 同一模型换 MBS，最优配置变号 | 70B fbc 相对 fbag：MBS8 −1.68%，MBS4 +2.21%，MBS2 +4.77% | F51 |
| MoE 上同一现象 | 只换 a2a 数据面，整步慢 13–18%；去掉每层 host 同步，整步快 10.3%（1.115×） | F24、F55 |

**机理（F50）**：本平台上，拷贝引擎往另一个进程的显存写数据时，host 会被拉回 GPU 进度附近（约拉回 GPU 落后量的 25%）。这和拷贝次数、大小、分叉写法、API 都无关。AG 先推后算，每次调用都把 host 的提前量清零。RS 先算后推，这个代价被自己的 GEMM 盖住。三种改法（槽位多份、换等待流、改分叉写法）位级都对，整步都没变好，所以这是平台代价，不是 bug。

**在线探测有偏（F44）**：通信上下文（对称堆 + 拷贝流）一旦建立，释放后仍会改变后续引擎操作的速度。所以在训练中现场试几种配置本身就会测歪，只能离线预测。

### 创新点 2（主）：两级预测器，决定开不开、在哪开

- **第一级（算子级代价模型）**：每个调用点预测原版、重叠、拆批的时间，带安全门。安全门的意思是：悲观估计也要比原版快 2% 才选。留一模型检验 97 个调用点：0 格比原版慢，几何均值 1.121–1.139×，高于总用重叠的 1.101× 和静态 M 阈值的 1.120×，拿到事后最优收益的约 83%。
- **第二级（整步控制面项）**：每次融合 AG 调用让 GPU 空等 e = k·D（D 是每层周期 GPU 时间，D 小于截止点时成立），把 e 加进整步预测再选 AG 子集。8 卡样本内 5/5，留一 4/5，16 卡样本外 2/2，而且 27B 和 70B 选出的最优配置相反，两个都选对。
- **RS 部分正在细化**（11-09 批次）：原来的 RS 截止点混了三类 op（o_proj 融合、fc2 融合、独立梯度 RS），正在拆开测。

### 支撑（写进评测，不列贡献）

- 训练整步：Megatron 27B / 70B，8 卡和双机 16 卡，对空对照 1.054–1.079×。
- 推理：vLLM 完整 LLaMA3-70B，8 卡 1.14–1.17×，16 卡 TP8×PP2 1.19–1.22×，输出逐 token 一致。
- MoE：整层免同步 1.115×，作为控制面论点的第二组对照。免同步 a2a 本身有 DeepEP / MORI-EP 先例，写成框架实例。

### 已知局限（要如实写）

1. 推理上第一级偏保守：vLLM 上 plan 比四处全开慢约 9%（单机）/ 3%（双机）。11-09 试过"推理关安全门"，但留一检验里 7/97 格选得比原版慢，已撤回，原因待归因臂查清。
2. 第二级只用 5 个整步点拟合，截止点只能夹在区间里。
3. F50 是 DCU/HIP 上测的，A800 上是否成立待测。

## 4. 用已有工作说明控制面创新

原则：不说"首次发现控制面开销"，因为 DMA-Latte、FiCCO、DeepEP 都碰到过。我们能说的是：**首次在训练整步上把控制面作为决定重叠收益的主因来刻画，并把它写进选择重叠方法的代价模型。**

| 工作 | 它对控制面做了什么 | 没做什么（我们的增量） |
|---|---|---|
| **FiCCO**（AMD，arXiv 2512.10236，MI300X） | 承认 CPU 发射开销存在，但认为"图捕获可以缓解"，正文略去（p.5）；有离线静态启发式（OTB×MT 对机器阈值，16 个场景命中 81%） | 只有算子级结果；启发式不含控制面项；没有整步数据。我们的数据表明在 eager 训练里控制面是主因，而且在 DTK 上图捕获会把多流串行化或死锁（F37），不是可选项 |
| **DMA-Latte**（AMD，arXiv 2511.06605） | 精细拆解单次 DMA 拷贝的 control / schedule / copy / sync 四个相位，小尺寸非拷贝相位最多约 60% | 单次拷贝粒度、算子级和推理 KV 拉取；没有跨 rank、跨层的整步效应，也没有用于选择重叠方法。它的 prelaunch / poll 是"控制面可被引擎侧机制部分消除"的方向，讨论节引用 |
| **MORI gemm_ar**（AMD 开源库，2026-09） | 按目的地旋转 + SDMA 直推 + 本地 fp32 求和；用静态 M 阈值决定是否融合，README 自己承认阈值定错过 | 静态阈值不随整步变化；没有控制面模型。它是置换序和算推同序的时间上更早的先例，**必须引用** |
| **DeepEP** | 点名 MoE 接收计数的 host 忙等；低延迟模式免 host 同步 | 只做通信，不做选择；没有整步分解。MoE 免同步的标准引用 |
| **PyTorch Async-TP** | 分块厂商 GEMM + 拷贝引擎 P2P，每次调用有全局屏障 | 总开不选；DCU 上初始化失败（论文写明），A800 上做基线 |
| **TokenWeave、MORI 等静态阈值** | 按 token 数或 M 阈值开关 | 阈值和整步时间无关；我们实测同一模型换 MBS 最优会变号，静态阈值做不到 |
| **Centauri、Oases** 等调度搜索 | 自适应选重叠策略或切分 | 叙事文档记的是"只建模算子本身"。**这两篇本地没有精读，引用前要核对原文** |

可以在论文里放心说的三句：
1. "现有重叠系统默认能重叠就重叠，最多调怎么重叠。我们证明在训练整步里，是否重叠、在哪重叠本身就是需要决策的问题。"（F17、F49、F51）
2. "我们首次把 host 控制面代价写进重叠方法的选择模型，并给出它随每层 GPU 时间变化、有截止点的形式。"
3. "在线探测在本平台上原理上有偏，因此规划必须离线完成。"（F44；先例没有这条）

不能说的：首次自适应选择重叠策略（FiCCO、TokenWeave、Centauri 已有）、首次发现 DMA 控制开销（DMA-Latte）、首次置换序推送（MORI）。

## 5. BW1000 这边还剩什么

RS 细化做完以后，**BW1000 上还不能完全收尾**。原因是 DCU 的基线对比必须在 BW1000 上跑，A800 跑不了 DCU 的数字。

| 项 | 状态 | 卡时 | 必要性 |
|---|---|---|---|
| RS 组拆分（11-09 批次） | 运行中 | 约 3 | 定第二级 RS 部分 |
| vLLM 归因臂（只开 QKV / 只开 fc1） | 未做 | 约 1.5 | 定推理第一级怎么修，或写成局限 |
| DCU 算子级基线统一表 | 部分有 | 约 3–5 | **必做**，见下 |

**DCU 基线现状**（来自 10-28 的移植记录）：
- flux、Syncopate、FlashOverlap 都已移植到 DCU，并统一到 vendor GEMM + RCCL 串行口径。flux R=8 0.41 / 0.63 / 0.88×，Syncopate RS 0.32–0.53×、AG 0.05×。
- 当时有一张"四方合并表"：我们的 RS 在所有共享格上都最快。
- 问题：这些数字用的是当时的旧内核（v9ring），而且各自 harness 不同，跨列只能比原始 ms。论文主表用的是冻结后的 DX。所以要用冻结代码、和算子级主表同一组形状重跑一遍，出一张统一的表。
- Triton-distributed 和 Async-TP 在 DCU 上能否跑，要先查当时的结论（Async-TP 记为初始化失败）。
