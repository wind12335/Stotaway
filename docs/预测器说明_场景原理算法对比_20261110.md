写于 2026-11-10。覆盖 `planner/` 截至 11-09 22:23 版本的代码（该改动尚未提交 git），并纳入 11-09 夜启动的 RS 拆分批次（`e2e/megatron/chain_rs_split_1109.sh`，未跑完）。

术语（首次出现处白话解释）：
- **调用点**：一层 Transformer 里 GEMM 和集合通信挨着的四个位置——QKV（注意力输入投影，先 AG 再 GEMM）、o_proj（注意力输出投影，先 GEMM 再 RS）、fc1（MLP 第一层 gate_up，先 AG）、fc2（MLP 第二层 down，先 GEMM 再 RS）。AG = AllGather 全收集，RS = ReduceScatter 规约分发。
- **原版**：厂商 GEMM（hipBLAS）+ RCCL 集合通信，串行执行，Megatron 一字不改。**重叠方法（DX，创新点 1）**：厂商 GEMM 不动，用拷贝引擎按块把数据推给对端、与 GEMM 并行。**拆批**：把 batch 拆成 2/4 份，一份的通信和下一份的 GEMM 同时跑。
- **整步**：一次完整训练迭代（前向 + 重算 + 反向 + 优化器）。**层周期**：一个 micro-batch 走完一层的前向 + 重算 + 反向；**D** = 每层周期 GPU 时间 = 整步时间 ÷（层数 × micro-batch 数）。
- **对称堆**：每张卡预留的一块各卡互相可见的显存，重叠方法的推送目的地。
- **安全门**：预测器的"宁可不赚、不能变慢"规则，见 §3.3。

## 0. 摘要

预测器（创新点 2）在**训练/推理开始前**为每个调用点决定用原版还是重叠方法（拆批暂未接入训练，只参与预测）。它分两级：第一级是算子级代价模型，按形状预测每个调用点各做法的时间，带安全门（悲观估计仍比原版快 2% 才选）；第二级是整步控制面项，把"融合 AG 每次调用让 GPU 空等 e = 0.0096 × D（D < 205 ms 时）"这条平台定律（F50）加进整步预测再决策。两级合起来的判决记录：第一级留一模型检验 97 个调用点 0 格比原版慢、收益捕获约 83%；第二级 8 卡样本内 5/5、留一 4/5、双机 16 卡样本外 2/2（且 27B 和 70B 的最优配置相反，两个都选对）。

一句话定位（继承 `docs/论文2创新点与相关工作定位.md`）：现有重叠系统默认"能重叠就重叠，最多调怎么重叠"；本预测器回答的是"**在真实训练整步里，重叠什么时候才赚、在哪个调用点开**"，答案由控制面（host 发命令一侧的代价）决定。

## 2. 使用场景

### 2.1 训练（主场景）：Megatron，单机 8 卡与双机 16 卡

- 车辆：27B（hidden 5120 / ffn 17408 / 32 层）与 70B（8192 / 28672 / 8 层截层），TP=8 + 序列并行，seq 4096，bf16，full 重算。16 卡 = TP8 × DP2（跨机只走 DP 梯度同步，重叠全部发生在机内 TP 通信上）。
- 接入方式：`e2e/megatron/run.sh` 的 `plan` 臂——同批若有 base 臂则把其实测整步中位数喂给 `--step-ms`，否则用 GEMM 探测文件粗估；预测器输出报告落盘 `plan_<臂名>.md`，并在 base / fbag / fbc / fcq / fcl 里选一个实际执行。
- 端到端战绩（加速比 = 原版整步 ÷ 该配置整步；"对空对照"= 扣掉环境本身影响后的纯重叠收益，论文头条口径）：

| 平台 | 模型 | MBS | 预测器选的 | 对原版 | 对空对照 | 比没选的配置 | 数据 |
|---|---|---|---|---|---|---|---|
| 8 卡 | 27B | 8 | fbag | 1.060× | 1.057× | 快 3.05%（对 fbc） | F33/F17 |
| 8 卡 | 70B | 8 | fbc | 1.064×(fbag) | 1.063×(fbag) | 快 1.68%（对 fbag，4 次均值） | F33、F27/39/41/42 |
| 16 卡 | 70B | 8 | fbc | 1.068× | **1.079×** | **快 3.46%**（对 fbag，两遍同号） | F52 |
| 16 卡 | 27B | 8 | fbag | 1.049× | **1.054×** | **快 2.77%**（对 fbc，两遍同号） | F52 |

16 卡两行是**样本外检验**：预测器参数全部来自 8 卡数据，16 卡上只读一次原版整步时间做决定，两个模型都选对且两遍同号。

### 2.2 推理：vLLM prefill（只用第一级）

- vLLM 只有前向，第二级不适用（§1.2），plan 臂 = 第一级按调用点选择。LLaMA3-70B 完整 80 层、M16384：plan 选了 o_proj + fc2 开重叠，对原版 1.066×（8 卡）/ 1.159–1.181×（16 卡 TP8×PP2）。

- 输出一致性门（自然文本 192 题）192/192 逐 token 一致——预测器选的配置不引入输出差异。

### 2.3 MoE：专家 MLP 路径选择（`planner/moe_plan.py`）

- 单卡、秒级、不建通信上下文：对给定专家形状在 Megatron 原版 SequentialMLP（逐专家一对 GEMM）与免同步 dropless grouped GEMM（虚拟组大小 B ∈ {1024, 2048, 4096}）之间选。B 重要是因为 hipBLASLt 按网格形状选算法——11-01 实测 Qwen3-30B-A3B 专家形状上 B=512/1024 比 B=2048 慢最多 1.8×。
- 路由偏斜（token 落到各专家的数量不均）对 grouped GEMM 几乎无影响（固定网格，F53），所以在偏斜的合成路由上做的规划对任意路由成立。
- 示例（data/moe_plan.json，E16_H2048_F768_T32768）：原版 12.91 ms，gg2048 9.77 ms，选 gg2048，1.32×。
- 整层免同步的端到端结果（sfl 1.116×、门 192/192）属于创新点 1 的 MoE 层，不是预测器的判决，此处只作场景说明。

### 2.4 为什么离线规划、不做在线试探（两条平台定律）

1. **在线探测有偏（F44）**：在本平台，一个做法的通信上下文（对称堆 + 拷贝流）一旦建立，即使释放，也会改变之后引擎操作的速度。训练中现场试几种配置，试的过程本身就把后面的测量测歪。所以决策必须**训练前一次做完**，选定后整个训练不变。
2. **规划输入极轻**（都不建通信上下文）：模型形状 + MBS；单卡测 4 个 GEMM（每形状几秒，`gemm_probe.py`，16 连发 × 8 次取中位）；原版配置短跑 ≤3 次迭代读整步时间。合计分钟级、单卡。

## 3. 原理

### 3.1 要解决的问题：最优组合随形状变号

没有任何一种做法在所有调用点、所有形状下最快。同一 70B 模型只换 MBS（每次处理的样本数），实测最优就三次变号：

| 70B 的 MBS | 实测最优 |
|---|---|
| 8（D=273 ms） | fbc（四处全开重叠） |
| 4（D=134 ms） | fbag（RS 两处开，AG 两处原版） |
| 2（D=77 ms） | base（四处原版） |

静态规则（如"M ≥ 阈值才融合"）表达不了"同一模型随 batch 变号"，这是预测器存在的理由。

### 3.2 两级架构

```
输入：形状(H,F,heads,kv,层数) + MBS + [原版短跑整步时间]
  │
  ├─ 第一级（算子级，每个调用点独立）costmodel.py
  │    预测 {原版, 重叠, 拆批2, 拆批4} 的时间 → 带安全门的选择
  │
  ├─ 第二级（整步控制面项）planner.py + step_planner_v3.py
  │    AG 两处：把每次融合 AG 的 GPU 空等 e 加进整步预测，选子集
  │    RS 两处：按每调用点截止点（11-09 起）开关
  │
  └─ 输出：4 个调用点各用哪种做法 + 可部署配置名 + 逐行理由
```

第一级看得见算子、看不见跨算子的平台代价；第二级补的就是第一级看不见的那部分。

### 3.3 第一级：算子级代价模型（`costmodel.py`）

**平台标定**（一次性，从算子级实测表拟合）：
- C_rccl(B)：RCCL 传 B MB 的时间，RS、AG 各一条直线 a0 + a1·B；
- C_dx(B)：重叠方法自己的纯通信时间，RS 侧直接测到（直线）；AG 侧测不到，设 Cx = k·B，k 在 0.002–0.05 对数网格 40 点上与系数一起搜索。

**三种做法的时间公式**（G = 该调用点单卡 GEMM 实测时间）：
- 原版：T = G + C_rccl(B) + h0（h0 固定开销）；
- 重叠：T = a1·G + a2·Cx + a3·max(G, Cx) + h1。max(G,Cx) 是理想重叠（谁长取谁）；a1·G 补"GEMM 被通信抢带宽变慢"，a2·Cx 补"首块和末块藏不住"，h1 是一次融合调用的固定 host/控制开销；
- 拆批 N：预测相对原版的加速比 r，log r = w0 + w1·log(G/C_rccl) + w2·log B + w3·log(G/N)。含义：计算通信越等长拆批越有效、每份 GEMM 太小则拆了反而亏。

系数按**相对误差最小二乘**（权重 1/T）拟合，RS / AG-up / AG-gate_up 三类各一套。

**安全门**：每个做法取"预测过于乐观幅度" log(实测/预测) 的 80% 分位 q，预测时间乘 exp(q) 得悲观估计；悲观估计仍比原版快 2% 才选，否则原版。效果是**从不选得比原版慢**（97 格检验 0 格违例），代价是漏掉一部分小赢（vLLM 偏保守即来源于此）。

**训练数据**：`data/cells.json` 99 格（去异常后 97 格）= 11 个公开 dense 模型（Qwen3-8B 到 Llama3.1-405B，形状全部核对自公开 config，`shapes.py` 注明出处）× M ∈ {8192, 16384, 32768} × 4 调用点，两个计时口径（单次 / 16 连发）。

**验证（留一模型：拿掉一个模型用其余 10 个拟合，预测这个模型）**：

| 指标 | 单次 | 连发(b2b) |
|---|---|---|
| dx 时间预测误差 MAPE | 6.7%（最大 19.5%） | 9.2%（最大 27.6%） |
| 选中最快方案 | 69/97 | 66/97 |
| 相对最优平均损失 | 1.93%（最差 37.18%） | 2.58%（最差 24.58%） |
| **选中方案比原版慢的格子** | **0** | **0** |
| 几何均值加速：预测器 | 1.142× | 1.139× |
| 几何均值加速：总用重叠 | 1.029× | 1.101× |
| 几何均值加速：静态 M 阈值 | 1.100× | 1.120× |
| 几何均值加速：事后最优 | 1.163× | 1.167× |

收益捕获 = (预测器−1)/(事后最优−1)：连发口径 (1.139−1)/(1.167−1) ≈ 83%（`docs/预测器原理.md` 引用的 83% 即此口径；单次口径约 87%）。静态 M 阈值基线 = TokenWeave / MORI 式"M ≥ T 才用重叠"，T 取训练模型上最优值——预测器稳定高于它。

### 3.4 第二级：整步控制面项

**现象**：第一级会把 27B/70B 的 AG 两处都判成重叠（算子级确实快），但整步实测四处全开（fbc）常输给只开 RS（fbag）：27B MBS8 +3.05%、27B MBS4 +3.26%、70B MBS4 +2.21%、70B MBS2 +4.77%（70B MBS8 −1.68% 是唯一赢点）。

**机理（F50，11-01 定位，2 卡探针 + 消融）**：本平台（DCU/HIP）上，拷贝引擎往**另一个进程的显存**（对称堆）写数据时，host（CPU 发命令一侧）会被拉回到 GPU 进度附近——每次约拉回 GPU 落后量的 25%，与拷贝次数、大小、分叉写法、API 均无关；同进程跨卡与本卡拷贝不触发。重叠方法的每次推送都是这一类（每卡一进程）。融合 AG **先推后算**：每次调用把 host 的提前量几乎清零，GPU 干完手上的活就要等 host 重新发命令，形成空泡 e；RS **先算后推**，被自己的 GEMM 盖住一部分。三种改法（槽位多份、确认挪门流、分叉改写值）位级正确但整步无效——判定为平台代价而非 bug，必须进模型。

**模型（AG 两处）**：每次融合 AG 调用的 GPU 空等 **e = 0.0096 × D（当 D < 205 ms），否则 0**。D = 每层周期 GPU 时间；层越长 host 越来得及重新领先、空等被盖住。开重叠的 AG 调用点集合 S 的整步变化 = Σ_S 2×(重叠−原版) + 2×e×|S|（乘 2：每个 AG 调用点在前向和重算各调一次；第一级差值来自算子级模型）。在 {都不开, 只 QKV, 只 fc1, 都开} 里选预测整步最快的，且预测至少快 1%（STEP_MARGIN，防噪声误判）才开。

拟合与检验（`step_planner_v3.py`，5 个实测整步点）：

| 点 | D (ms) | 实测反推 e (ms) |
|---|---|---|
| 27B MBS8 | 136.7 | 1.69 |
| 27B MBS4 | 74.4 | 0.65 |
| 70B MBS8 | 273.2 | ≈0（−0.13） |
| 70B MBS4 | 134.1 | 0.96 |
| 70B MBS2 | 76.9 | 0.73 |

四条候选定律留一检验（e=0 / e∝D / e∝D 带截止 / e=常数−份额·D）：采用律 **e∝D 带截止** 4/5 选对、平均绝对误差 1.44 个百分点，唯一选错的 70B MBS8 是唯一高于截止点的点（拿掉它就没数据估截止点）。k=0.0096；截止点被数据夹在 137–273 ms 之间取中点 205。全体拟合样本内 5/5。

**RS 两处（11-09 更新中）**：RS 组实测相对原版 27B MBS8 −6.37%、70B MBS8 −7.44%、70B MBS4 −5.80%、70B MBS2 +3.1%（唯一输点，10-29 测）。旧规则 D < 111 ms 回退原版（截止点只夹在 80–143）；新规则每调用点独立截止（o_proj 95 / fc2 110，**预估值待 §1.4 批次拟合**）。

**D 的来源**（三选一，规划时自动）：给定 `--dcycle`；`--step-ms`（原版短跑）× 0.94 ÷ 层数 ÷ micro-batch 数（0.94 = fbag/原版实测比，范围 0.926–0.955）；都没有则 15.4 × 四处 GEMM 之和粗估（实测比值 12.2–20.0，脚本会警告结论可能不准）。

### 3.5 更新后的完整决策流程（`planner.py` plan()）

```
1. M = seq × MBS；G = 探测文件或单卡现测；D = §3.4 三来源之一
2. 第一级：每调用点预测 {stock, dx, split2, split4}
   stage1  = 全部候选里带安全门的最优（含拆批）
   stage1d = 可部署候选 {stock, dx} 里带安全门的最优（拆批未接入训练）
3. RS 调用点（每点独立截止）：
   final = dx  当且仅当 (D ≥ 该点截止点 或 推理模式) 且 stage1d = dx；否则 stock
   （推理模式直接 final = stage1d）
4. AG 调用点：
   训练：候选 = 第一级原始预测 dx < stock 的点（此处不用逐算子安全门，
         门槛由整步 1% 余量承担——这是 step_planner_v3 验证过的规则）；
         枚举子集，整步变化 = Σ 2·(dx−stock) + 2·e·|S|，取预测最快且 ≥1%
   推理：final = stage1d（每点独立，第一级选择即最终）
5. 输出：训练模式把 AG 子集映射到 base/fbag/fbc/fcq/fcl（RS 只许两处同开，
   部分开启=未定义配置）；推理模式输出逐调用点清单
```

### 4.2 使用方法（命令行）

```bash
# 训练规划（推荐给原版短跑整步）：
python3 planner/planner.py --model 70b --mbs 8 --step-ms 18892
# 任意形状：
python3 planner/planner.py --hidden 8192 --ffn 28672 --heads 64 --kv 8 --layers 80 --mbs 4 --step-ms 9655
# 推理模式（11-09 新增，只用第一级）：

```

输出报告逐行列出：形状、G、第一级四候选预测、第一级选择（含拆批）、最终可部署选择、理由（例如"第二级：每次融合 AG 调用让 GPU 空等 1.36 ms，抵掉了算子级收益"），末尾给可部署配置名。拆批被选中时会标注"未接进训练"。

### 4.3 关键工程决策（为什么这样设计）

- **离线而非在线**：F44（§2.4），在线试本身有偏。
- **GEMM 用实测不用模型**：单卡探测几秒钟，消掉 GEMM 库版本/形状特例的全部不确定性；模型只负责通信与重叠部分。
- **AG 候选用无门原始预测 + 整步 1% 余量当门**：逐算子 2% 安全门是为"单独换这个算子不变慢"设计的；AG 决策是整步子集选择，门放在整步层（step_planner_v3 验证的就是这条规则）。
- **预测器只用 CPU + 一次单卡 GEMM 探测**：规划动作本身不碰通信上下文，不会触发 F44。
- **常量集中可审计**：K_E、D_CUT、两 RS 截止点、STEP_MARGIN、FBAG_OVER_BASE 全在 planner.py 头部，注释写明数值来源与区间。

## 5. 与已有研究成果的对比

原则（继承 `docs/论文2创新点与相关工作定位.md`）：不说"首次发现控制面开销"（DMA-Latte、FiCCO、DeepEP 都碰到过）；能说的是**首次在训练整步上把控制面作为决定重叠收益的主因来刻画，并把它写进选择重叠方法的代价模型**；以及**在线探测在本平台上原理有偏，因此规划必须离线完成**（先例没有这条）。

| 工作 | 它做了什么 | 它没做什么（= 我们的增量） |
|---|---|---|
| **TokenWeave / MORI 式静态阈值** | 按 token 数或 M 阈值开关融合；MORI gemm_ar（AMD 开源，2026-09）按目的地旋转 + SDMA 直推 + 本地 fp32 求和，用静态 M 阈值决定是否融合（README 自认阈值定错过） | 阈值与整步时间无关。我们实测同一 70B 只换 MBS 最优三次变号，静态阈值表达不了；MORI 的置换序推送在时间上早于我们，论文必须引用 |
| **FiCCO**（AMD，arXiv 2512.10236，MI300X） | 承认 CPU 发射开销但认为图捕获可缓解（正文 p.5 略去）；离线静态启发式（OTB×MT 机器阈值，16 场景命中 81%） | 只有算子级结果；启发式不含控制面项、无整步数据。我们测得 DTK 上图捕获会把多流串行化或死锁（F37），不是可选项 |
| **DMA-Latte**（AMD，arXiv 2511.06605） | 精细拆解单次 DMA 拷贝的 control/schedule/copy/sync 四相位，小尺寸非拷贝相位最多约 60% | 单次拷贝粒度、算子级与推理 KV 拉取；无跨 rank 跨层的整步效应，也不用于选择重叠方法。其 prelaunch/poll 是"控制面可被引擎侧机制部分消除"的方向，讨论节引用 |
| **DeepEP** | 点名 MoE 接收计数的 host 忙等；低延迟模式免 host 同步 | 只做通信不做选择、无整步分解。MoE 免同步的标准引用；我们的 MoE 免同步层写成框架实例 |
| **PyTorch Async-TP** | 分块厂商 GEMM + 拷贝引擎 P2P，每次调用全局屏障 | 总开不选；DCU 上初始化失败（论文写明）；A800 上做基线 |
| **Centauri、Oases 等调度搜索** | 自适应选重叠策略或切分 | 定位文档记为"只建模算子本身"。**这两篇本地未精读，论文引用前必须核对原文** |
| **论文 1（AnchorOverlap，本组 EuroSys'27 在投）** | 集合通信–GEMM 重叠的运行时协议 + 两阶段**配置搜索**（窗口/通道/前沿占比等"怎么重叠"） | 搜索假设重叠总开着（只调 how，不调 whether/where）；推理前向 only；无控制面项。论文 2 的票据交接协议骨架继承自它（双盲期按第三方引用），预测器的 whether/where 决策是独立增量 |
| **本预测器** | 两级：算子级代价模型（含拆批、安全门、97 格留一验证）+ 整步控制面项（e=k·D 带截止，训练/推理模式分明）；离线、输入轻量；0 格比原版慢的保证 | — |

不可声称的（有先例）：首次自适应选择重叠策略（FiCCO、TokenWeave、Centauri）、首次发现 DMA 控制开销（DMA-Latte）、首次置换序推送（MORI）。

## 6. 局限与待办（如实）

1. **两个 RS 截止点是预估值**（95/110 ms），待 11-09 拆分批次跑完拟合；若相差 <10 ms 合并回单一截止点。批次现状：P1 半程（k1 死亡、第二遍未跑），P2/P3 未跑，续跑约 3 卡时。
2. **第二级只用 5 个整步点拟合**（两个模型）；AG 截止点只夹在 137–273 ms（取中点 205），RS 截止点区间 80–143。论文按区间写。
3. **推理第一级偏保守未解决**：vLLM plan 比 dx 慢约 9%（单机）/ 3%（双机）；关安全门已试且否决（7/97 格变慢，§1.3）；归因臂（只开 QKV / 只开 fc1，约 1.5 卡时）排在 RS 拆分之后。
4. **F50/F44 是 DCU/HIP 上测的**，A800 上是否成立待测——迁移后第一个判决性实验就是 F50 探针（`probes/copy_hostblock_heap.py`）；不成立则第二级控制面项要按新平台重新标定。
5. **拆批未接入训练**（E2 待办），可部署选择暂为二选一；报告会标出算子级最优是拆批的调用点。
6. **D 粗估口径**（15.4×ΣG）误差大（实测比值 12.2–20.0），仅无整步短跑时兜底，报告会警告。
7. 11-09 更新后 `--selftest` 未重跑（预期 5/5，见 §1.5），提交前应跑一次。
