## 二、P0：影响主实验的具体问题

### P0-1 原生 Qwen3.6-27B 训练载具还没接入

- **现状**：`results/bw1000_oprs_20261126/status.md` 明确指出 `SW_MODEL=27b` 是稠密 GPT 车辆（hidden=5120、ffn=17408、32 层、随机初始化/mock），不是原生 Qwen3.6。`workloads.py` 虽有 `qwen36_sites` 形状生成，但 `tools/oprs_plans.py` 的 workload choices 和 `e2e/megatron/run_oprs.sh` 没有可运行的 Qwen3.6 入口。
- **与 A800 对照**：A800 表 `nvidia/results/单机8卡端到端与预测器结果_20261113.md` 记录 Qwen3.6-27B 文本配置、64 层、TP8、seq4096、MBS2、随机初始化/mock。Qwen 可能存在不同层型和不同投影形状，不能压成旧 GPT 的固定四个单一形状。训练与推理目标不能互换：70B 是推理，Qwen3.6-27B 是训练。
- **要做**：检查 Hygon Megatron 是否支持该模型真实结构和算子；接入训练载具、所有适用投影及 forward/backward，按真实层型记录站点 manifest，计划导出和框架 hook 的命中要一致。设置 `M=8192/16384/32768` 时可用 seq4096、MBS2/4/8，但核对内存和其他参数。若原生结构暂无法接入，清楚标记阻塞并并行完成算子、预测器和 70B 推理；旧载具仅为单独实验，不能改名当作 Qwen3.6 的结果。

### P0-2 TP8 尚未完成真实通信与框架验证

- **现状**：本提交的 `status.md`、`report.md` 明确新协议所有 TP≥2 未测。TP1 上沒有设备间通信，证明代码接线、形状与部分数值正确，但不能证明 8 卡通信、收益、派发稳定性或 E2E。
- **要做**：8 卡 smoke：AG/RS 各路径、8 rank 正确性、连续调用、plan SHA 一致、DUSHMEM/对称内存初始化和释放；然后少量真实模型站点验证，再全表。两种 B 均单独验证运行路径，记录实际命中、失败原因与环境。已经存在旧 8 卡 DEO 实验，保留历史结果，不把它与新版方案实测合并。

### P0-3 Triton-distributed 的 Hygon 内核依赖本机研究工作树

- **现状**：`src/stowaway/oprs/backends/triton_dist.py` 从 `OPRS_TRITON_DIST_ROOT` 导入 DCU port，默认 `/root/private_data/tri-dist-hygon`，不在本次 OPRS 仓库提交里。环境文档记录该工作树基于 `40f48db` 且有 861 项未提交修改；当前仓库里的 `data/Triton-distributed` 不能自动替代 Hygon DCU 版。
- **要做**：验证目标机器该目录确实存在、版本和运行代码 hash，并保存具体内核与依赖的快照或可重现补丁及许可证信息；至少将源码 hash 和 dirty 状态写进每次数据 provenance。不要声称 Git 提交 `40f48db` 单独足以重现有未提交改动的工作树。只跑本项目需用的内核，避免编译无关库。

### P0-4 静态 shape 支持与 E2E 覆盖需保持透明

- **现状**：`platform.static_support` 的 Triton-dist 条件：AG 的 M/N 是 128 倍数，K 是 16 倍数且 M/TP 是 1024 倍数；RS 的 M/N/K 是 256 倍数。对于 99 个原表点，迁移方静态统计 87/99、代表图 18/21；不支持 `gemma3-27b` 的 3 个 RS 点和 `qwen25-72b` 的全部 9 点。旧 `bw27b` 的 TD 有 2/4 站点静态满足约束；Llama 4/4 是静态结果，不是 TP8 实测。
- **要做**：如实保存 unsupported（不画 0）。能较低成本通过既有原理修复或 padding 的地方，可将适配前后当完整路径对照，必须计入 pad、裁剪、布局恢复的时间并重新做正确性；不改模型维度充当成功。`always_B` 含 serial fallback 时报告每站点实际覆盖，别写成四处都使用 B。

### P0-5 输入站点不在训练样本范围、评估泄漏风险

- **现状**：原 99 点是 dense FFN 的 `ag_gu/ag_up/rs`，不覆盖所有 QKV/o_proj 真实形状；`data.py:usable` 只选 `kind=operator`，`kind=site` 不能自动用于训练。单卡计划有外推，实际 dispatch 的预测与时间方向相反；TP1 数据不具备 TP8 性能含义，但暴露范围判断问题。
- **要做**：保存真实 Qwen、Llama 站点的 M/N/K 与各路径计时，区分 held-out 评估与部署 calibration；`provenance.out_of_range` 要进入结果。决定使用站点数据训练时先实现显式策略并分清训练/验证来源；留族评估不得把被测族或相同目标站点泄漏进训练与残差库。每个 B 给自己的可用样本分母，不因 TD 缺 12 点把 Async 的 99 点也缩成 87。

### P0-6 E2E 当前产物主要是日志和 CSV，尚非约定的原始 JSON

- **现状**：`bench/oprs_matrix.py` 原生保存逐点 `.jsonl`；`tools/oprs_plans.py` 原生输出多份 JSON；`evaluate.py` 可输出完整预测 JSON。Megatron `run_oprs.sh` 主要是 `out_r*.log`、`step_ms.txt`、`e2e_training.csv`，vLLM 是 `voprs.csv`、日志、自然文本 `gatetext_*.json`，不应说两者已原生输出完整实验 JSON。
- **要做**：为 E2E 每个进程新增结构化原始 JSON（时间序列、方案、实际命中、模型与环境、退出状态、日志路径）；保持现有 CSV 作为派生汇总。不同臂单独文件，记录原始各轮，不能只转 CSV 均值成 JSON 冒充原始数据。

## 三、P1：实验解释和可复现性问题

### P1-1 训练反向执行不完全一致

`autograd.py` 中 Async-TP 和 Triton-dist 后端是前向融合、反向框架路径；DEO 的 row backward 默认可走 AG+dgrad（`OPRS_DEO_BWD=ag`），也可设 `stock`。A800 既有实验不同臂的反向可能不同。报告每站点的 forward/backward 路径；同平台比较时保留完整训练路径、loss 与梯度检查。为分离前向差异，可增加统一 `OPRS_DEO_BWD=stock` 的控制臂；无须将所有臂强行描述为完全相同实现。

### P1-2 测量粒度和 E2E 参数差异

A800 算子每点独立进程、各路径可能跨批；Hygon 新 `oprs_matrix.py` 每个进程可扫描多个点、每个点同进程交错测 serial 和各候选、每点前后正确性检查。都使用 16 连发、8 组，但开销边界及进程安排不完全相同。Hygon 训练驱动默认迭代第 3 步后取中位、16 步、ACC=8；A800 文档是第 4–12 步、GBS2。两平台可比较各自归一化结果，实验表必须准确写出差别；需要同配置对照时调整脚本并核对模型配置，不能把历史结果当同批。

### P1-3 旧值与新值的重测策略

BW 原 DEO 99 点已经有历史中心值，但日志没有八组原值；新结果独立保存，不取历史值和重测值的逐点最大值。`llama4-mav-d/ag_gu/M32768` 与 `qwen3-8b/rs/M32768` 在旧数据带异常标记，新采样复核串行 GEMM/通信和候选，保留所有原始值与标记；排除与包含异常点的统计各自明确分母。

### P1-4 E2E 消融与开销

`tools/oprs_tables.py choices` 已能离线对比 `base_ridge`、残差修正 `oprs`、固定 DEO、固定 B 和 oracle；迁移说明指出当前没有仅岭回归或 oracle 的 E2E 计划导出。主线先完成留族消融与 E2E 四种策略；若补 E2E 消融，再扩展 plan exporter，用真实站点实测生成 oracle，需记为事后上界。准备/加载时间和每次查表开销单独实测，不能由 1 卡数值推导 8 卡同步降低幅度。

### P1-5 安装与进程退出

`run_oprs.sh` 注释说明 Megatron 引擎臂可能出现 MPI 未 finalize 导致 mpirun 返回 1，而 Python 日志打印 `EXIT`；要检查各 rank 实际结束状态、完整日志和最终汇总，完善正确清理，避免将 mpirun 异常一律当成功。分布式超时、hang、数值失败必须保留原始记录。运行条件和权限随目标机器核对。

### P1-6 推理 3 个 M、2M 的真实上下文

vLLM 驱动的 M 是 chunk 长度，`ttft2` 实际请求为 2M；M32768 对应 65536 token。要记录配置、真实 prefill token、上下文支持、显存与输出；失败就是失败，不能将小于设定的 token 结果记成该 M 的成功。A800 历史有明确 RoPE 配置；保持已有模型设置并记录，让使用者知道两平台的设置差异。

### P1-7 平台算法与 E2E 参数匹配

旧 BW 二级预测器 `planner/step_planner_v3.py` 的控制面规则与新版 shape-only route-local residual 是两套不同方法。当前新 Hygon OPRS 复现的是新版基础算法，不等于整步控制面效应已输入新模型；应分别评估，不自行声称已融合。单卡开销、旧数据回放不能替代 TP8 拟合/测试。

## 四、给执行者的立即顺序

1. 拉取最新 hygon，保护未提交工作，核对版本与 `OPRS_TRITON_DIST_ROOT`，读配套的 `01_实验矩阵与启动脚本说明.md`。
2. 先跑 8 卡最小 smoke；能用的路径立即启动 21 点、接着补至 99 点，保存逐组 JSONL。不中断可继续推进时，在 CPU 侧编写计划和 E2E JSON 输出。
3. 同时补真实 Qwen3.6 训练载具和站点 manifest；Llama 推理可独立推进。按现有 JSON 计划逐个验证两种 B 的 TP8 派发。
4. 以新协议数据做留族预测器评估及 Ridge 消融，生成两种 B 各自的计划；训练与推理分别覆盖 M8192/16384/32768。
5. 运行真实模型 E2E，每个 B 单独 5 臂 × 2 轮；保存 JSON 原始结果与日志。更新实验覆盖与异常表，明确实际测到的模型、路径和精度。
