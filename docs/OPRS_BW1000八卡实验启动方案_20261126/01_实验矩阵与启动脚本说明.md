# OPRS：BW1000 单机八卡实验矩阵与启动脚本说明

基准审查版本：`hygon` @ `662a3e6e1122b6dfc1cad163b4ccd18407a83bf3`。本文交给 Hygon 端 AI：先读同目录 `02_迁移审查与待解决问题.md`，再核对本机分支 HEAD 和现有工作，沿用实际代码完善启动与输出。本文是任务规格，不冒充已生成或执行的 shell 脚本。

## 1. 本轮实验要比较什么、做多少

算子层面的外部对照限定为 **Async-TP、Triton-distributed**；`serial`（串行）是 1.00× 基准，**DEO 是我们的方法，也必须测**。算子图有 4 类路径：`serial / Async-TP / Triton-distributed / DEO`。预测及 E2E 每次固定一个外部后端 B，比较 `serial / always B / always DEO / OPRS(B+DEO+serial)`；两次分别以 Async-TP、Triton-distributed 为 B。不要把两个 B 混在同一方案。

按一个 BF16、TP8 主实验配置，实验类型为 **6 类**：①算子表；②真实模型站点采样与派发；③预测器留模型族评估与消融；④Qwen3.6-27B Megatron 训练 E2E；⑤Llama3-70B vLLM 推理 E2E；⑥系统准备、派发及依赖开销。为组织它们提出 **9 个启动脚本**（下一节）。脚本不是实验点数量。

| 工作 | 实验规模与统计方法 | 已有/新做 |
|---|---|---|
| 全量模型算子 | 11 模型 × 3 操作（`ag_gu,ag_up,rs`）× 3 个 M（8192、16384、32768）= **99 个形状**。4 类路径上限 396 个形状×路径测量项。静态规则下 TD 87/99、DEO 99/99、Async 99/99，因此预计 384 项可测：99 serial + 99 DEO + 99 Async + 87 TD；实际以 TP8 记录为准 | 历史 DEO 99 点保留；新协议缺 TP8 各路径及 8 组逐值 |
| 论文代表算子图 | 7 模型 × 3 操作 × M32768 = **21 个形状**；是上述 99 的子集，不再重复计入。TD 静态支持 18/21，其他 21/21，即预计 81 个形状×路径项 | 先测该子集，再 `RESUME=1` 补全到 99，不重复已经成功的点 |
| 实际调用点 | 两个模型各 4 种投影位置 × 3 个 M，理想下 **24 个逻辑站点×M**；Qwen3.6 实际结构可能有每层不同的多个形状，必须从真实模型采集后列完整 manifest，不能假设恰好 12 个训练形状；Llama 的重复形状可去重测量，保留对应站点映射 | 现有 `--sites` 有旧稠密 `bw27b_train` 与 `llama70_infer`；真实 Qwen3.6 需要先接入并生成 manifest |
| 预测器 | 全表一次，分别评估 serial/DEO、serial/DEO/Async、serial/DEO/TD；每组比较固定方法、基础岭回归、完整模型和 oracle；分别给 AG、RS、整体，以及各 M 的计数与结果 | 原 `choices` 已有基本留族评估；按 M 的独立汇总从逐点 JSON 离线生成 |
| 模型方案 | 2 任务 × 3 M × 2 个 B = **12 个方案集**；每集含 `manifest.json`、`oprs_<B>.json`、`always_<B>.json`、`always_deo.json`、`oprs_deo_only.json`、`null.json` | 训练以真实 Qwen3.6 为目标，推理以 Llama3-70B 为目标；集内方案数和执行臂数不同 |
| 训练 E2E | 每个 M、每个 B 各 5 臂：`serial / null / always_deo / always_B / oprs`，共 3×2×5 = **30 个臂配置**。每臂两次独立进程，则 **60 次进程运行**；每个 B 各自有本批串行和 null，以便比较 | 需先真正接入 Qwen3.6 训练载具；旧 bw27b 仅作载具验证，不计入 Qwen3.6 正式表 |
| 推理 E2E | 每个 M、每个 B 各 5 臂：`stock / sp_rccl / all_deo / always_B / oprs`，共 **30 个臂配置**，每臂两次独立进程为 **60 次进程运行**；每个进程产出 TTFT、2M、吞吐等不同指标，不将每个指标重复算作一臂 | Llama3-70B 真实权重、TP8；旧记录保留 |
| 调用点派发检查 | 对每个任务、每个 M、每个 B，实际执行 OPRS 方案中的站点：最多 **12 次方案检查**，每个方案条目数按真实 manifest；含串行命中及回退统计 | 只在站点/方案数据准备好后运行，不重复算入 99 个模型表点 |
| 可选扩展 | `oprs_deo_only`、执行开销分解、E2E 的基础岭回归/事后最优方案 | 前两项建议做；后两种 E2E 消融当前没有方案导出入口，作为扩展，不计入以上主实验数量 |

**注意**：每一臂×M 是一个实验配置，不是卡数；每个进程有多步或多个请求，不能当成多个独立进程。上表的 60+60 次 E2E 进程是完整 3 M、2 B、5 臂、两轮的上限计划；两个 B 的 serial、DEO 可共享只在同一个受控批次、相同载具/上下文条件且记录可追溯时成立。目标真实 Qwen3.6 未接入期间先运行其他已具备部分，最终不能把旧 GPT 结果改名为 Qwen。

## 3. 关键入口与先后顺序

先在 Hygon 节点确认依赖、实际提交、模型路径与各后端版本，再跑 01。然后用现有入口执行 02，示例（`$RUNROOT` 是自定义的新结果根目录）：

```bash
cd /path/to/Stotaway
export RUNROOT="$PWD/results/bw1000_oprs_20261126_formal"
NP=8 OUT="$RUNROOT/raw/operators/tp8_matrix" bash bench/run_oprs_matrix.sh --first-batch
NP=8 RESUME=1 OUT="$RUNROOT/raw/operators/tp8_matrix" bash bench/run_oprs_matrix.sh --table
```

当前 `--first-batch` 固定七模型的 M32768；`--table` 默认三个 M、99 个形状。已成功点可续跑，不做重复的基准实验；对报错单独保存状态后有针对性重跑。单独 B 不可用时先测其他方法，恢复后独立补采并记录各自 serial；并排图要说明是否使用同批分母。

站点入口例子（Llama，3 个 M；参数按该脚本实现核对）：

```bash
NP=8 OUT="$RUNROOT/raw/sites/llama70" bash bench/run_oprs_matrix.sh --sites llama70_infer --rows 8192,16384,32768
```

真实 Qwen3.6 的站点必须从训练实际模型与形状采集；**现有 `tools/oprs_plans.py` 的 `--workload` 选项没有 qwen36_train，现有训练 shell 也没有真实 Qwen3.6**。先完成该训练载具及方案导出，再测站点及 E2E。先使用可直接运行的 Llama 和模型算子工作，训练接口完成后接入队列。

已有计划示例，仅适用于该项目的**旧稠密 GPT 27B 载具**：

```bash
python3 tools/oprs_plans.py "$RUNROOT/plans/bw27b/M8192/async_tp" \
  --tp 8 --backend async_tp --workload bw27b_train --seq 4096 --mbs 2 \
  --data "$RUNROOT/raw/operators/tp8_matrix/samples_tp8_bfloat16.jsonl"
```

该命令只能验证旧载具方案，不是 Qwen3.6 训练的正式配置。Llama 方案使用 `--workload llama70_infer --rows 8192` 等，并确保真实模型 `config.json` 可读。采样集中的 `kind=site` 当前被 `usable()` 排除出训练；站点采样用于独立评估，不应写成已经自动加入拟合。按模型族留出时，禁止把目标族真实测量泄漏给对应留出折。

## 4. E2E 比较与可复现要求

训练一个 B 的 5 臂：`serial`、`null`、`always_deo`、`always_<B>`、`oprs`；两轮轮换先后顺序，保持每个臂完全相同模型/seq/MBS/重计算/精度。每步汇总方式必须显式保存并统一：A800 历史为第 4–12 步中位数、一次进程；现有 BW 驱动为第 3 步起中位数、默认 16 步、ACC=8，二者不是同配置。可以选择与 A800 一致的 12 步/窗口，或选择 BW 既有载具协议，但必须在 JSON 记录并分别报告；GBS、层数、真实模型结构与数据也要记录。

推理一个 B 的 5 臂：`stock`（原始 vLLM AllReduce）、`sp_rccl`（序列并行 AG/RS 串行）、`all_deo`、`always_<B>`、`oprs`。以 SP-RCCL 为该投影实验的 serial 参考，同时分别给出对原 vLLM 的比值；不能把两个基准混为同一个 1.00×。现有驱动默认 `ttft=1×M`、`ttft2=1×2M`、`thru=16×M`；3 个 M 分别为块长，2M 的 token 长度分别 16384/32768/65536，检查原模型最大上下文、显存及 vLLM 配置，记录实际处理 tokens 和任何实际配置变化。保证长度真实成功后才汇总，失败记录不生成性能值。

每个臂保留独立进程日志、退出状态、配置、方案 hash、每位置实际命中、每步时间/每请求时间、峰值显存及数值检查；容差以配置和日志明确记录，避免要求 token 逐一一致作为唯一判据。现有脚本会记录 `py_rc` 与 `mpirun rc`，MPI 非正常退出也应定位并改为正常清理，不能只凭一个 rc 认定全部成功。

## 5. JSON 数据契约与统计

1. **算子原始 JSONL**：一条 `(model, op, M,N,K, candidate)` 行，记录 `schema,kind,platform,tp,dtype,batch=16,repeats=8,warmup,run_order,serial_samples_ms,candidate_samples_ms,per_rank,serial_reference_median_ms,candidate_median_ms,speedup,correctness,status,source_files,commit`。候选不支持要写 `status=unsupported`，无数值而非 0。现有 `bench/oprs_matrix.py` 已有这些字段，优先复用。
2. `speedup = median(serial_samples_ms) / median(candidate_samples_ms)`。柱高度是两组耗时中位数之比，不是 8 个 speedup 的算术均值。绘制范围 `min/max(median(serial_samples_ms)/candidate_samples_ms[j])`；这是固定串行中位数下八组观测范围，不是置信区间。保留两组原始值以便后续改统计口径。
3. 同一形状、同一 dtype 和测量轮次内 serial 要一致；现有矩阵在同一点共享一个 serial。同批次、同精度、同计时范围才能称严格的多后端横向比较。异常点新旧记录分开保存。
4. **E2E 原始 JSON**：`schema, model, model_config, workload, tp, M, seq, mbs, dtype, backend, arm, round, plan_path, plan_hash, process_rc, per_rank_rc, step_ms[]/request_records[], warmup_policy, median_ms, hit_detail, fallback_detail, correctness, software_versions, commit, raw_log_paths`。训练保留 loss、反向与梯度验证记录；推理保留真实权重、token 数、TTFT/2M/吞吐、自然文本检查结果。
5. **预测 JSON**：每候选的输入、拟合路径、训练族、留出族、预测对数收益、预测选择、各候选真实耗时、真实最优、误差和慢点；按三套候选集合汇总，且 AG、RS、每 M 的分母均可追溯。留出模型时基础模型和残差库均不见留出族。
6. 单个模型配置的 E2E 汇报 `serial/arm` 与 `B/OPRS`；训练 null、推理 SP-RCCL 与原框架基线分开。不要将算子准确率直接当成整模型端到端正确率。

## 6. 完成标准

- 99 个算子形状有覆盖报告；三种方法分别记实测成功、unsupported、失败和数值检查。21 点主图是它的子集。确认每点八组原始记录可读。
- 两种 B 的三候选留族评估分别给结果；基础岭回归消融与固定方法、oracle 同时给出，输出每 M、AG/RS/总体分母。
- 两个模型、3 M 的站点 manifest 与计划集可追溯；各 plan 的执行命中与选择对应，空缺有原因。
- 训练以真实 Qwen3.6-27B 为主目标，推理以真实 Llama3-70B 为主目标。若训练结构仍未接入，报告具体阻塞，旧稠密载具独立注明；继续完成已能运行的实验。
- 两个 B 对应 E2E 各臂的原始 JSON、日志及 speedup 可复算；每种基准与每种 dtype 明确。最终报告同一批次下的 `serial vs B vs DEO vs OPRS` 和 `B/OPRS`。
- 暂不运行双机 16 卡；不增加 FlashOverlap、Syncopate 编译与实验。历史 16 卡和旧数据原样保留。
