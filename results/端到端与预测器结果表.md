# 端到端结果表与预测器结果表（海光 BW1000，单机 8 卡 + 双机 16 卡，Megatron 训练 + vLLM 推理）

- **加速比 = 原版整步时间 ÷ 该配置整步时间**（越大越好）。原版 = 厂商 GEMM（hipBLAS）+ RCCL 串行，Megatron 一字不改。
- **整步时间** = 每臂 14–18 次迭代，第 3 次起的中位数（ms/迭代）。每臂一个独立进程。"两遍"= 同一批次里该臂跑两次（ABAB 交错），表中写"第 1 遍 / 第 2 遍"。
- **对空对照**：空对照（fnull）的环境、对称堆、包装层和重叠方法完全一样，但一个算子都不接管。"对空对照"= 扣掉环境本身影响后的**纯重叠收益**，是论文头条口径；"对原版"是总差，另列。空对照相对原版的差值（−1.3% 到 +1.0%）来自对称堆的内存布局，正负号随环境变（F30 / F39-D4）。
- **只比同一批次内的数**。同一配置在不同日期的绝对时间可以差 5–7%（机器状态），跨批只看比值。
- 车辆：27B = hidden 5120 / ffn 17408 / 40 头 / 8 KV 组 / 32 层；70B = hidden 8192 / ffn 28672 / 64 头 / 8 KV 组 / 8 层（显存限制截层）。seq 4096，TP=8 + 序列并行，full 重算，bf16。MBS = 每张卡一次处理几条样本，M = 4096 × MBS。
- 16 卡 = TP8 × DP2（每台机器一个 TP 组，跨机只做 DP 梯度同步，走 RDMA），每张卡的计算量与 8 卡完全相同。
- 配置名：base = 原版；fbag = RS 两处（o_proj、fc2）用重叠方法、AG 两处（QKV、fc1）用原版；fbc = 四处全用重叠方法；fcq = fbag + 只 QKV 用重叠方法。
- 原始数据与逐条说明：`results/findings.md`（F 编号见各表）。

## 3. 单机 8 卡：AG 两处的选择（预测器第二级的全部实测点）

每格是同一批次内"开 AG 重叠的配置"相对 fbag（RS 两处用重叠方法，AG 两处用原版）的整步变化，负 = 开了更快。

### 3.2 规律
- 同一个 70B：MBS8 时 AG 两处开重叠方法更快（4 次 −0.58% 到 −2.79%，均值 −1.68%），MBS4 和 MBS2 时更慢（+2.21%、+4.77%）⇒ **最优配置随形状变，不能按模型一刀切**。
- 机理（F50）：本平台对另一个进程显存的引擎拷贝会把 host 拉回 GPU 进度附近；融合 AG 先推后算，每次调用让 GPU 空等。每层 GPU 时间够长（≥ 约 205 ms）时空等被盖住。三种改写法都无效，是平台代价。

## 6. 单机 8 卡 vLLM 推理（11-02，LLaMA3-70B prefill）

- 模型：LLaMA3-70B **完整 80 层、真实权重**，bf16，TP=8，eager；vLLM 0.11 das 分支。每个 prefill 块 M = 16384 个 token（对应 Megatron MBS4）。
- 臂：stock = 原版 vLLM（TP AllReduce）；rccl = 序列并行写法（AR 拆成 RS + AG），四处原版 RCCL；dx = 序列并行写法，四处都用重叠方法；plan = 序列并行写法，每处按预测器第一级选（推理没有重算和反向，不用第二级）。
- 计时：ttft = 1 条 16384 token 提示；ttft2 = 1 条 32768 token（两块）；thru = 16 条 16384 token。每臂独立进程，ABAB 两遍，取全部重复的中位数（ttft / ttft2 各 6 次，thru 4 次）。两遍之间差 ≤ 0.6%。
- 原始数据：`results/raw/vllm/M16384/`；详表：`results/vLLM结果表.md`。

### 6.1 prefill 时间（s）

| 臂 | QKV / o_proj / fc1 / fc2 | ttft | ttft2 | thru | 对原版 | 对 rccl |
|---|---|---|---|---|---|---|
| stock | AllReduce（原版） | 2.186 | 4.975 | 34.995 | 1.000× | — |
| rccl | 原版 ×4 | 2.118 | 4.840 | 33.942 | 1.031–1.032× | 1.000× |
| **dx** | **重叠 ×4** | **1.879** | **4.347** | **29.898** | **1.144–1.170×** | **1.114–1.135×** |
| plan | 原版 / 重叠 / 原版 / 重叠 | 2.050 | 4.705 | 32.871 | 1.057–1.066× | 1.029–1.033× |

- 序列并行改写本身快约 3%；重叠方法的纯收益看 dx 对 rccl：**1.11–1.13×**，比训练整步（1.06–1.08×）高，因为推理只有前向，没有重算 / 反向稀释。
- **预测器在推理上偏保守**：第一级在 M16384 给 QKV、fc1 选原版（算子级表 Llama3-70B M16384 的 AG+GEMM 只有 1.01× / 0.98×，再加 2% 安全门），实测四处全开比 plan 再快 8–10%（ttft 1.091×、ttft2 1.082×、thru 1.099×）。即 vLLM 前向里 AG 两处开重叠是赚的，算子级表低估了它们。原因未查（推测原版 RCCL AG 在车内比孤立测时慢）；要坐实需只开 QKV / 只开 fc1 两臂（约 1.5 卡时，未跑）。安全门的作用仍在：plan 没有比原版慢。

### 6.2 输出一致性

提示 = 模型目录里的真实文本（README / LICENSE / USE_POLICY 重复拼成正好 16384 个 token，在重复内容的句中截断），续写是有把握的照抄；每臂 4 个提示 × 48 个贪心 token，与 stock 逐 token 比。

| 臂 | 与 stock 相同的 token | 首 token logprob 差（只来自 SP prefill） | 相同前缀上 max logprob 差 |
|---|---|---|---|
| rccl | 192/192 | 0.0000 | 0.0027 |
| dx | 192/192 | 0.0000 | 0.0090 |
| plan | 192/192 | 0.0000 | 0.0090 |

随机 token 提示的检查判断不了正确性：下一个 token 分布几乎是平的（最大概率 2–10%），dx / plan 从第 3 个 token 起就与 stock 不同，连只改写不重叠的 rccl 的 logprob 也差到 0.91。以本表为准。

### 6.3 16 卡代码路径的单机验证（TP4 × PP2）
